# ICC Profile Tool — 使用手冊 {#icc-profile-tool-user-manual src=38bba1de}

**ICC Profile Tool**（**ICC 設定檔工具**，簡稱 profiletool）是一套在瀏覽器中執行的工具，用於檢視、驗證 **ICC.1** 與 **ICC.2 (iccMAX)** 色彩設定檔，並對其進行往返編輯。它完全在您的瀏覽器中執行——不需上傳，也不需安裝——所使用的是 [iccDEV](https://github.com/InternationalColorConsortium/iccDEV) 的 WebAssembly 建置版本；iccDEV 是 ICC 官方的 IccProfLib 示範實作。

**您可以做的事：**

- **瀏覽標頭**——128 位元組設定檔標頭中的每個欄位，皆解碼為易讀的字串。
- **瀏覽標籤目錄**——列出每個標籤的簽章、類型、位元組偏移、大小與填充位元組。按一下任一標籤即可展開完整的類型專屬說明（與 iccDEV `wxProfileDump` 的「Describe」檢視輸出相同）；對於帶有可視資料的標籤，另提供內嵌的**視覺化**：色調響應曲線、色度圖、CLUT 與色域影像、命名色散佈圖，以及單點的**轉換求值器**。
- **驗證**——執行 ICC Profile Assessment Working Group 檢查清單（安全性／符合性／品質），每項檢查都有判定結果，並可依類別篩選。
- **往返編輯**——將設定檔轉換為 XML 或 JSON，在內建的程式碼編輯器中編輯，再轉換回 ICC 並重新驗證。儲存按鈕會下載編輯後的二進位檔。
- **串接設定檔**——在**連結**分頁中，將集區中的設定檔拖入有序的鏈條，然後將其烘焙為 **DeviceLink**、透過它**轉換影像**（可完整控制輸出編碼、壓縮、平面配置與 ICC 內嵌），或**轉換色彩資料集**。
- **處理 HDR**——依 ICC.1 HDR ColorSpace 設定檔規則（第 8.7.1 條）檢查設定檔、讀取其 cICP 代碼點，並繪製其在任意顯示餘量下的自適應增益曲線。**HDR** 分頁可在您的螢幕上顯示一張 HDR 影像，**設定 → 環境**則會回報此瀏覽器與螢幕的能力。
- **從 chardata 啟動**——將 [chardata](https://chardata.colourbill.com/) 中已載入的設定檔直接在此開啟，位元組透過 `postMessage` 在瀏覽器內傳遞。
- **以 URL 啟動**——開啟一個連結，讓工具載入網路上的設定檔，並可選擇指定要開啟的分頁（例如 `…/profiletool#url=…&tab=VAL`）。

所有處理都在用戶端進行。設定檔位元組絕不會離開瀏覽器分頁。

<div class="note">
<strong>ICC.2 (iccMAX) 的支援尚不完整。</strong>ICC.2 設定檔的載入、檢視、驗證與往返編輯都與 ICC.1 相同——驗證檢查清單包含 iccMAX 專屬檢查，光譜 PCS 與多處理元件 (MPE) 標籤皆可解碼，轉換引擎也以完整的 iccMAX 堆疊建置。尚未涵蓋的部分：多段式 <strong>ICS</strong>（Interchange Color Space，交換色彩空間）工作流程、套用轉換時選擇 V5 <em>子設定檔</em>，以及部分 ICC.2 設定檔的反向搜尋。較少見的 ICC.2 功能可能仍有缺口，將隨各版本逐步補齊。
</div>

<div class="note">
<strong>HDR ColorSpace 設定檔的支援依據的是草案。</strong>HDR 檢查、<code>headroomAdaptiveGainCurveTag</code> 檢視與 HDR 分頁，實作的是 ICC.1 HDR 修訂案的現行版本。該修訂案尚未正式發布，因此在發布前細節仍可能變動。
</div>

## 1. 工作區 {#1-the-workspace src=4bc9350f}

profiletool 是一個**多設定檔工作台**。視窗分為三個部分：

- 左側的**設定檔**窗格——即您所載入之所有內容的*集區*；
- 右側的**畫布**，頂端有五個分頁——**設定檔**、**比較**、**連結**、**光譜**、**HDR**；
- 右側邊緣的**設定**側欄（請參閱[設定面板](#2-settings-panel)）。

### 載入設定檔 {#loading-profiles src=2cd0f653}

載入檔案有兩種方式：

- 按一下「設定檔」窗格頂端的**載入設定檔**，選擇一個或多個檔案，或
- 將檔案**拖放**到「設定檔」窗格上。

您可以載入 `.icc` / `.icm` 設定檔，*也*可以載入影像。拖入 **TIFF、PNG、JPEG、HEIC 或 AVIF** 時，工具會擷取其中的**內嵌 ICC 設定檔**並加入集區。它只讀取檔案的中繼資料，從不讀取像素。對於 HEIC 與 AVIF，工具會逐一走訪檔案的 box 結構，因此在任何瀏覽器中都能運作，包括無法顯示這些格式的瀏覽器。**JPEG XL** 檔案也會被拒絕：其設定檔壓縮在碼流 (codestream) 內，而 profiletool 目前尚不支援解壓縮。與 HEIC 共用容器格式的影片與相機 RAW 檔（MP4、QuickTime、Canon CR3）不會被視為影像。**OpenEXR** 或 **Radiance HDR**（`.hdr`）檔案會被拒絕並註明原因：這兩種格式都沒有存放 ICC 設定檔的欄位。OpenEXR 以色度座標描述其色彩，Radiance HDR 則透過選用的 `PRIMARIES` 檔頭行描述。若要*檢視*影像，請使用 [HDR 分頁](#4-7-hdr-tab)。**＋ 從 .cube 新建**按鈕可由 `.cube` LUT 建立 DeviceLink。結果會加入集區，並在**設定檔**分頁中開啟；在您按下**儲存 ICC 設定檔**之前，不會下載任何檔案。

設定檔若在前 36 個位元組內含有 `acsp` 簽章，且能通過 IccProfLib 的 `ValidateIccProfile` 剖析，即會被接受。未通過的檔案會列在拒絕摘要中並附上具體原因；其位元組不會被保留。

### 「設定檔」窗格 {#the-profiles-pane src=04750126}

已載入的設定檔會依**設定檔類別**（Input、Display、Output、DeviceLink、ColorSpace、Abstract、Named Color……）分組到可收合的區段中。符合 ICC.1 第 8.7.1 條的 **HDR ColorSpace 描述檔**則在最上方另有專屬區段（它們屬於 ColorSpace 類別，因此從 ColorSpace 區段中獨立出來），並依傳遞函數分為**線性傳遞函數**與**非線性傳遞函數（PQ、HLG）**，每一列都以標記顯示其傳遞函數。這項區分在 [HDR 分頁](#4-7-hdr-tab)中很重要：只有線性傳遞函數的設定檔才能指定給 OpenEXR 或 Radiance HDR 影像。每一列會顯示檔名，以及類別、色彩空間、版本與大小的標記；僅能部分剖析的設定檔會另加標示。使用 **A–Z** 按鈕可循環切換排序方式（載入順序 → 遞增 → 遞減），按列上的 **×** 可移除該列，拖曳窗格右側邊緣的把手可調整寬度——或將窗格完全收合。

按一下可選取一列；Ctrl/Cmd 加按一下可切換選取，Shift 加按一下可選取範圍。**將列從集區拖到分頁上**，即可開始使用這些設定檔。

<div class="note">
<strong>集區僅在本次工作階段有效。</strong>不會上傳任何內容，也不會保存任何內容——您的檔案系統才是長期存放之處。重新載入頁面會清空集區。
</div>

### 分頁 {#the-tabs src=034c9677}

| 分頁 | 功能 |
|---|---|
| **設定檔** | 檢視**單一**設定檔——標頭、標籤、驗證、分析、XML、JSON。在此拖入新的設定檔會取代目前的設定檔。 |
| **比較** | 疊加顯示**兩個或以上**設定檔的色域。 |
| **連結** | 將設定檔串接成 DeviceLink，或透過它們轉換影像／資料集。 |
| **光譜** | 將多張單通道光譜影像組裝成一個多通道 TIFF。 |
| **HDR** | 在您的螢幕上顯示**一張** HDR 影像，並提供 SDR ↔ HDR 控制項。請參閱 [HDR 分頁](#4-7-hdr-tab)。 |

「光譜」與「HDR」分頁直接接受影像檔，而非集區中的設定檔。其他分頁各自保有一組設定檔，以可移除的標籤片顯示在分頁列下方，分頁本身則顯示數量標記。您載入的第一個設定檔會自動在**設定檔**分頁中開啟；之後，請從集區拖到您要的分頁上。將檔案直接拖放到分頁上，可一次完成載入集區*並*放入該分頁兩個動作。

<div class="note">
<strong>大小限制：</strong>載入器會拒絕任何大於 256 MB 的檔案。實際的設定檔通常遠小於 10 MB；這項上限只是為了防止惡意的拖放或 postMessage 耗盡分頁的 WASM 堆積記憶體。
</div>

## 2. 設定面板 {#2-settings-panel src=3bf599d9}

按一下螢幕右側邊緣的 **⚙** 按鈕（行動裝置上則是右上角的齒輪圖示）即可開啟「設定」。面板會滑出覆蓋在內容之上，不會改變內容的版面大小。

⚙ 下方還有兩個按鈕：

- **?** 會在**應用程式內**開啟本指南，以從右側滑入、覆蓋在視窗上的窗格呈現。其標頭有一個搜尋框——輸入文字即可醒目標示相符項目，再用 `Enter` / `Shift+Enter`（或 `˄` `˅` 按鈕）逐一切換；按 `Escape` 清除搜尋，再按一次 `Escape` 則關閉窗格。
- **✉** 會在新的瀏覽器分頁中開啟 colourbill.com 上的聯絡表單。

面板分為兩組：**顯示**與**環境**。若要調整面板寬度，請拖曳其左側邊緣（220–560 px）；寬度設定會被記住。

### 背景 {#background src=1450fe76}

在**淺色**、**深色**與**系統**（跟隨作業系統偏好）三種佈景主題之間切換。所選設定會跨工作階段保留。在**系統**模式下，應用程式會訂閱 `prefers-color-scheme`，並在作業系統主題變更時自動切換；明確選擇「淺色」或「深色」則會解除該監聽。

### 數字格式 {#number-format src=af65622c}

選擇各設定檔檢視中數值的顯示方式——**十六進位**或**十進位**。

### 語言 {#language src=38c60535}

覆寫介面語言。**系統預設 (…)** 會偵測瀏覽器的地區設定並使用最接近的支援語言，括號內顯示該語言的原生名稱，讓您知道它選了哪一種。翻譯範圍涵蓋應用程式介面：「設定檔」窗格、分頁標籤、「連結」「光譜」與「HDR」工具、「標籤」中的 HDR 增益曲線檢視、包括「環境」及其原因說明在內的設定面板，以及本指南的介面文字。有些文字不會翻譯：
- 由 IccProfLib 產生的字串——標籤說明、驗證訊息、標頭欄位名稱——來自 C++ 程式庫，以英文顯示。
- 瀏覽器旗標名稱保留英文，以便與瀏覽器本身的旗標頁面一致。
- 「環境」面板中的**顯示事件**記錄保留英文，以便原封不動地貼到錯誤回報中。
- 本指南遵循相同的設定，但 HDR 章節除外：在 HDR 支援仍屬測試版、內容仍在變動期間，這些章節保留英文。若某章節的英文內容在其翻譯最後更新後又有修訂，也會以英文顯示並附上註記，直到翻譯跟上為止。

支援的語言：English、Français、Deutsch、Italiano、Español、Português (PT)、Português (BR)、Svenska、中文（简体）、中文（繁體）、日本語、한국어。chardata 的設定面板提供相同的語言組合，因此在其中一個應用程式切換語言，另一個應用程式也能提供一致的閱讀體驗。

### 環境 {#environment src=2eb1ea2c}

顯示**此**瀏覽器、平台與螢幕的能力，讓您在某種格式或 HDR 功能無法使用時能了解原因。由上而下依序為：

- **摘要**——瀏覽器與作業系統，以及螢幕是否回報支援 HDR。
- **瀏覽器旗標**（Chrome、Edge、Opera、Brave）——*Experimental Web Platform features* 是否已開啟。這個旗標會啟用 HDR 畫布，並讓網頁能讀取螢幕的 HDR 餘量。
  - 當已知該旗標為關閉時，該方塊會醒目標示。若此瀏覽器沒有可用的 WebGPU，則標示為**必要**，因為此時 HDR 畫布是算繪 HDR 的唯一途徑；否則標示為**選用**。
  - 檢視設定檔從不需要此旗標。
  - 網頁無法開啟或變更瀏覽器旗標。請按**複製**，將網址貼到網址列，把旗標設為 *Enabled*，然後重新啟動瀏覽器。
- **顯示器資訊**——**HDR 顯示器**、**廣色域**（sRGB、Display P3 或 Rec. 2020）、**像素比**，以及目前使用的 **HDR 畫布路徑**（`float16-canvas`、`webgpu` 或無）。當您將視窗拖到這些特性不同的螢幕上時，這些資訊會自動重新整理。切換會在視窗大部分移到新螢幕上時發生。
- **識別顯示器**（Chromium 系瀏覽器）——請求權限以得知視窗位於哪台顯示器上。允許後，即使在外觀相同的顯示器之間移動，面板也會重新整理，並列出**目前顯示器**，且在瀏覽器提供時顯示 **HDR 餘量**（需啟用上述旗標的 Chrome），例如 *1.35 檔（≈ SDR 白的 2.55 倍）*。若您拒絕了權限，請在網站設定中變更。
  - 餘量是指高於 SDR 白的空間，因此在筆記型電腦的內建 HDR 面板上，**調高亮度時餘量會下降**（SDR 白變亮，而面板峰值不變），調低亮度時則會上升。觀看 HDR 時，請調低亮度。
  - 在 Windows 上，亮度變更後幾秒鐘，待顯示驅動程式回報後才會出現新數值。當視窗移到另一個螢幕，或 Chrome 重新成為作用中的應用程式時，也會重新整理。
- **顯示事件**——可收合的記錄，列出最近 20 次重新整理及各自的觸發原因。回報顯示問題時很有用。
- **格式表**——每種格式一列（ICC 設定檔、TIFF、PNG、JPEG、OpenEXR、Radiance HDR、AVIF、HEIC/HEIF、JPEG XL），回答三個問題：
  - **檢查**：能否讀取內嵌的設定檔？
  - **顯示**：能否顯示像素？
  - **HDR**：能否算繪出高於白色的亮度？

  將游標停在某列上，可查看 ✕ 背後的原因；無法顯示的格式會在表格下方列出並附上原因。圓點標示的是由 profiletool 自行解碼的格式，在所有瀏覽器中表現一致。除了 JPEG XL（其設定檔壓縮在碼流內）之外，所有格式的**檢查**欄都是 ✓。

## 3. 設定檔檢視 {#3-profile-views src=ccf59d34}

將設定檔從集區拖到**設定檔**分頁上即可檢視。此分頁會顯示一列包含檔名與**儲存 ICC 設定檔**按鈕的工具列（編輯後還會出現 *● 已修改 — 尚未儲存* 標記），其下方是檢視器：標題列（檔名 · 位元組大小 · IccProfLib 版本 · 有效性標記）以及檢視器自己的分頁列。

該標記彙總了**驗證**報告的結果：沒有任何檢查失敗或警告時為綠色的**通過**，至少有一項檢查為警告時為琥珀色的**警告**，任何一項檢查失敗時為紅色的**失敗**。

<div class="note">
<strong>僅部分剖析的設定檔：</strong>如果設定檔損壞到驗證器只能讀取其結構，將會顯示警告橫幅，且只提供<strong>標頭</strong>與<strong>標籤</strong>分頁——驗證、分析、XML 與 JSON 都會隱藏，因為這種設定檔不應被套用。
</div>

### 3.1 標頭 {#3-1-header src=45c71bd0}

一個兩欄表格，列出 ICC 設定檔 128 位元組二進位標頭中的每個欄位。數值會透過 IccProfLib 的 `CIccInfo` 解碼為易讀的字串（展開簽章、格式化日期、轉換定點數值）。**設定檔 ID**（標頭中的 MD5 雜湊值）會顯示在頂端醒目標示的長條中。

### 3.2 標籤 {#3-2-tags src=90f22730}

一個六欄的格線，列出設定檔標籤目錄中的每個標籤：

| 欄 | 意義 |
|---|---|
| `#` | 在目錄中的位置（從 1 起算） |
| `Name`（標籤名稱） | 易讀的完整名稱（例如 `profileDescriptionTag`） |
| `ID` | 4 字元簽章（例如 `desc`） |
| `Offset`（偏移） | 距檔案開頭的位元組偏移 |
| `Size`（大小） | 標籤資料的位元組大小 |
| `Pad`（填充） | 此標籤與下一個標籤之間的填充位元組 |

標籤的**類型**簽章（例如 `descType`、`mft2`、`mAB`）會連同偏移與大小顯示在展開後的標籤頂端。

標籤依偏移排序。**填充**欄會以顏色標示——`Pad < 0`（標籤重疊，不符合規範）以紅色顯示；`Pad > 3`（填充超出規範）以琥珀色顯示。

**按一下任一列**即可就地展開（手風琴式——一次只展開一個標籤）。展開的詳細內容最後一定是完整的類型專屬說明——等同於執行 IccProfLib 的 `CIccTag::Describe(verbosity = 100)`。對於含有大型 CLUT 或曲線的標籤（例如 `A2B0`、`B2A0`），說明中會包含每一個格點或曲線點。

在該說明上方，帶有可視資料的標籤會顯示一或多個**內嵌視覺化**，各自位於可收合的區段中：

| 標籤類型 | 視覺化 |
|---|---|
| 色調曲線（`rTRC`/`gTRC`/`bTRC`/`kTRC`） | 色調響應曲線與恆等線對照繪製；曲線表收合在其下方。 |
| RGB 著色劑（`rXYZ`/`gXYZ`/`bXYZ`）與白點（`wtpt`） | CIE 1931 色度圖，並醒目標示相應的原色（或白點）；著色劑／白點資料顯示在下方。 |
| LUT 轉換（`A2B0–3`、`B2A0–3`、`gamt`、`pre0–2`） | 輸入端與輸出端的色調曲線（疊加顯示，依著色劑以顏色區分，並有可切換曲線的圖例）；以影像呈現的 CLUT 網格；**色域影像**（針對設定檔的 `gamutTag`，以顏色區分——中性 = 色域內，紅色 = 色域外）；**求值器**（見下文）；以及收合的原始資料表。 |
| 命名色／著色劑表（`ncl2`/`nmcl`/`clrt`/`clot`） | 將各顏色繪製於 CIELAB a\*b\*（及 CIE xy）圖上的散佈圖；表格收合在下方。 |
| 與編碼無關的代碼點（`cicp`） | **代碼點**：色度基色、轉換特性、矩陣係數與全範圍旗標，各自以 ITU-T H.273 定義的名稱標示。H.273 未指派的數值以及非零的保留位元組都會被標示。 |
| 自適應增益曲線（`headroomAdaptiveGainCurveTag`） | **指定顯示餘量下的增益**，標籤儲存替代影像時另有**增益曲線**。請參閱下方的 *HDR gain curves (HAGC)*。 |

<div class="note">
<strong>格式錯誤的資料絕不會被隱藏。</strong>如果曲線或其他可視元素未通過 IccProfLib 的驗證——例如 gamma 退化為 0 的色調曲線——該區段仍會盡可能算繪，並顯示 ⚠ 警告及程式庫提供的確切原因，而不會默默省略圖表。
</div>

#### 轉換求值器 {#the-transform-evaluator src=c70f94b4}

對於 LUT 轉換（`A2B*` / `B2A*` / 預覽標籤），**求值**區段會直接使用 IccProfLib，將該標籤的轉換套用到您提供的單一顏色上——不經任何外部色彩引擎。方向依標籤而定（`A2B*` 為裝置 → PCS；`B2A*` 為 PCS → 裝置），轉換意圖也由標籤決定（`…0` 感知、`…1` 相對比色、`…2` 飽和度）。

- 輸入可以是**浮點值**（裝置通道值，或以一般 Lab/XYZ 單位表示的 PCS 值），或在標籤含有 CLUT 時，以**網格點**索引（網格上的節點位置）輸入。
- 輸出會**同時**以內部正規化的 0–1 編碼與可讀單位（PCS 結果為 Lab/XYZ）顯示。

色域標籤（`gamt`）沒有求值器——它是單通道的色域內／色域外對應圖，而非可反轉的轉換；改為顯示其色域影像。

### 3.3 驗證 {#3-3-validation src=b72d6c69}

對已載入的設定檔執行 **ICC Profile Assessment Working Group** 檢查清單，並以報告形式呈現。這些檢查來自 iccDEV 的 `iccPawgReport` 工具，編譯為獨立的 WebAssembly 模組，只在您第一次開啟此分頁時才會下載。（同一份報告也決定標題列中的有效性標記，且在以 URL 啟動時可用 `VAL` 或舊版代碼 `PAWG` 開啟。）

每項檢查都歸入**安全性**、**符合性**或**品質**之下，並帶有一個判定結果。含有 HDR 內容的設定檔還有第四組：**HDR**。其第一項檢查會回報該設定檔是否為符合規範的 ICC.1 **HDR ColorSpace 設定檔**（第 8.7.1 條），其餘檢查則檢驗該條文所依賴的 HDR 中繼資料：

| 判定 | 意義 |
|---|---|
| **通過**（PASS） | 檢查成功 |
| **警告**（WARN） | 值得檢視的非致命問題 |
| **失敗**（FAIL） | 設定檔不符合此項檢查 |
| **缺口**（GAP） | 此項檢查無法完整評估（例如尚未實作） |
| **不適用**（N/A） | 此項檢查不適用於此設定檔 |
| **未執行**（NOT RUN） | 已略過此項檢查 |

頂端的摘要列以彩色標記統計各判定結果的數量。**按一下標記即可篩選**下方的報告——藍色光暈標示目前顯示的類別，數量為零的標記則無作用。例如，關閉**通過**（PASS）與**不適用**（N/A），即可只看警告與失敗項目。

### 3.4 分析 {#3-4-analysis src=9478bc94}

由設定檔的色彩轉換衍生出的整體設定檔品質分析——由專屬的 WebAssembly 模組（iccDEV 視覺化引擎）計算，此模組只在您第一次開啟此分頁時才會下載，並以應用程式本身的樣式繪圖。

每項分析都是一個可收合的區段，而且**全部預設為收合**。這是刻意的設計：每個區段都需要對設定檔執行一次完整的轉換運算，因此由您明確選擇要開啟哪一項，而不是一切換分頁就同時啟動六項分析。結果會被快取，因此重新開啟區段可立即顯示。不適用於所載入設定檔的區段，會改為顯示簡短的*不適用*說明（例如，矩陣/TRC 顯示器設定檔沒有可分析的裝置↔PCS CLUT）。

#### 特性檔統計 {#profile-statistics src=f2d4f2db}

針對**一個**所選轉換意圖的整體設定檔指標，由兩個清單方塊與一個核取方塊控制：

- **轉換意圖**——感知／相對比色／飽和度／絕對比色。
- **往返類型**——要回報哪一種精確度指標（見下文）。
- **使用 MPE（色彩）標籤**——關閉 = 使用比色查找表；開啟 = 使用多處理元件／色彩標籤。此選項對色域內概覽沒有作用，在該模式下會停用。

表格顯示**色域體積**（單位 ΔE\*ab³，為裝置 → PCS 的 `A2B` 轉換所包圍的範圍，以體素化邊界並計算內部單元的方式測得），以及所選往返的 ΔE\*ab **最小值／平均值／標準差／P90／最大值**。其下方是 ΔE 分佈直方圖——相對頻率長條加上累積頻率曲線——以及誤差最大的 `L, a, b`；PRMG 類型還會顯示設定檔是否隱含感知參考媒體色域。

四種往返類型：

- **色域內概覽 (RT0)**——將裝置值格線轉到 PCS、再轉回裝置、再轉到 PCS；在兩次 PCS 結果之間測量 ΔE\*ab。這是快速的色域內穩定性檢查。
- **反演 + 色域 (RT1)**——每個裝置色的 PCS 值，與其經過一次 Lab → 裝置 → Lab 往返後的 PCS 值之間的 ΔE\*ab。同時反映反演精確度*與*色域映射。
- **可重現性 (RT2)**——第一次與第二次往返之間的 ΔE\*ab：反映重複往返的穩定程度，不受第一次往返之色域裁剪影響。
- **PRMG 互通性**——位於感知參考媒體色域內的 PCS 顏色進行一次往返；ΔE 分佈可反映跨設定檔的互通性。

直方圖下方的**依明度的往返 ΔE**，回答了彙總數字無法回答的問題：反演在色調階的*哪個位置*出問題，以及問題*深入色域多遠*。

它取樣 32 個明度層級。在每個層級上取 64 個**位於色域邊界上**的點，再將這些點朝中性軸方向收縮至其彩度的 80 %、50 % 與 20 % 重複取樣——總共 8,192 個點，每個點都個別繪製，各層級之間以虛線分隔。

請逐段閱讀。在同一段內，點從左側的色域表面排到右側的中性區，因此誤差應在該段內**逐漸下降**：靠近邊界的顏色最難反演，靠近中性的顏色最容易。若某一段的誤差一路到中性都居高不下，表示設定檔在該明度上有問題。最高的尖峰則標示出色域邊界本身反演得最差的明度層級。

每個種子點在構造上都位於色域內，因此您看到的是真正的 `B2A`/`A2B` 不一致，而不是顏色因無法達到而被裁剪。請注意，此圖有其**獨立的**取樣方式——刻意偏重色域邊界——因此其平均值與最大值會高於上方表格，且不可與之比較。此圖會依循轉換意圖，但不受往返類型影響。

若設定檔缺少某項指標所需的裝置↔PCS 轉換，會顯示*不適用*說明；裝置色彩空間過大而無法取樣時，會回報為已略過，而非錯誤。

#### 極值比色 {#extrema-colorimetry src=be6c9597}

設定檔再現範圍的兩端——印刷操作人員通常最先查看的數字。

- **白點**——**零著色劑**時的顏色，也就是未印刷的承印物。
- **黑點**——將 PCS 黑（L\*=0, a\*=b\*=0）送入所選的 `B2A` 表，取得設定檔為黑色*所選擇*的墨量，再將該墨量經由 `A2B1` 讀回而得。
- 兩者都以**相對**與**絕對**比色顯示。絕對比色呈現承印物本身的顏色（偏藍的白紙讀數約為 L\* 95、b\* −4）；相對比色則以理想白重新參照。若兩欄完全相同也屬正常——表示媒體白恰好與光源一致。沒有媒體白點標籤的設定檔只顯示相對值。
- **黑點處的墨量**與 **TAC**——該黑點各通道的墨量及其總和：總墨量覆蓋率，即墨量限制值。

由於每個 `B2A` 表都會為黑色選擇各自的墨量，黑點在不同意圖之間確實會不同——因此提供了轉換意圖選擇器。

其下方是**實地與最大彩度**：針對每個墨色角點（C、M、Y、R、G、B 與 K），顯示其落點的色相／彩度／明度，以及從未印刷承印物到該角點途中所找到的最高彩度點。這些列是經由 `A2B1` 測得的，因此**不會隨意圖選擇器改變**。在表現良好的設定檔上，兩列會一致。若最大彩度在實地*之前*就已達到，該列會被標示：超過該點後，增加的墨量不再提升彩度，只會使顏色變暗。

**僅限輸出（印表機）設定檔**——此分析假設零著色劑即為未印刷的承印物。各色相表格還需要 **CMYK 或 CMY** 裝置色彩空間：n 色 (nCLR) 設定檔的通道可依任意順序命名，無法得知哪個通道是「青」，因此表格會如實說明，而不加以猜測。

#### 中性軸墨量 {#neutral-axis-inking src=aa5449e4}

沿中性軸（a\*=b\*=0）從白（L\*=100）掃描到黑（L\*=0），經由設定檔的 `B2A`（PCS → 裝置）表，繪出設定檔在沿途鋪設的各裝置著色劑用量——即經典的 GCR／中性灰構成曲線。每個裝置通道一條曲線，依著色劑以顏色區分。

分色曲線上還會疊加另一條曲線：

- **L\* 輸出（色調）**——色調響應：中性軸經過設定檔往返後，實際落在哪個明度。從其形狀可讀出兩件事。曲線低於對角線，表示灰色會比要求的更暗。更有用的是，曲線會**在設定檔所能達到的最暗明度處變平**——那段平台*就是*媒體黑點，應與上方「極值比色」區段的結果一致。

**僅限輸出（印表機）設定檔**；其他設定檔類別會顯示說明。

#### 暗部的用墨 {#ink-usage-in-shadows src=e62016b7}

在一個固定且刻意偏暗的明度上，沿 a\*b\* 平面的四條直線路徑——0°、45°、90° 與 135°——經由所選的 `B2A` 表，分別繪出所得的分色結果。

由於路徑上每個樣本的 L\* 都相同，任何著色劑的突然跳變或反轉都只來自色相與彩度的處理。這正是暗部色域映射瑕疵的特徵，在印刷品上會表現為暗部區域的色階斷層或突然的色偏。這些路徑從色域外遠處出發，穿過色域，再從另一側離開，因此您也能看出設定檔從何處開始截斷。

明度平面會自動選定：位於設定檔的藍色角點與 C、M、Y、R、G 中最暗者的中間。對於感知與飽和度表，明度會先從媒體黑點延展到 PCS 黑——這些表預期黑色位於該處——此區段會同時回報補償後的平面與原始平面。

**僅限輸出（印表機）設定檔**，且與上述各色相表格相同，有 CMYK/CMY 的限制（平面由墨色角點推導而來）。

#### 經中性軸的原色墨路 {#primary-inking-paths-through-neutral src=cb510c25}

三條路徑——青→紅、洋紅→綠、黃→藍——各自從一個原色角點出發，在兩端點的中間明度處**穿過中性軸**，到達對側角點，經由所選的 `B2A` 表，繪製為分色圖。

這是「暗部的用墨」在色域內的對應分析。前者的路徑刻意延伸到色域外，以暴露色域映射瑕疵；此處則**每個樣本在構造上都位於色域內**——兩端點都是設定檔本身的原色，轉折點位於中性軸上。因此，沿這些路徑出現的著色劑跳變、折角或反轉，不能歸咎於色域裁剪：而是 CLUT 平滑度的缺陷。中性轉折點位於每張圖的中點，您應在該處看到平衡的中性灰構成。

對於感知與飽和度表，明度會依該意圖進行黑點補償，與「暗部的用墨」完全相同。

**僅限輸出（印表機）設定檔**，且同樣有 CMYK/CMY 的限制（角點與各色相表格來自相同來源）。

#### 墨量統計 {#ink-usage-statistics src=191fd7cd}

設定檔所鋪設的各著色劑用量，以平均覆蓋率及**佔總量的比例**呈現——即該分色的耗墨特徵。

表格沿中性軸加總每種著色劑，並回報其平均覆蓋率及其佔全部墨量的百分比。佔比欄是診斷重點：它是設定檔中性灰構成的指紋（偏重青色的灰平衡與偏重黑色的灰平衡讀數截然不同），而且與取樣數量無關。

第二個表格——**所有色域上及色域內顏色**的墨量使用——列為*待完成*：它需要尚未建置的色域邊界構造。

**僅限輸出（印表機）設定檔。**

#### CLUT 影像 {#clut-image src=a3fec568}

將裝置↔PCS 轉換的色彩查找表拼貼成一張影像，並提供選擇器以選擇要檢視哪個轉換意圖的表（`A2B0`–`A2B3`、`B2A0`–`B2A3` 及預覽表）。可用來一眼看出表中的結構性損壞。使用畫布上的控制項可縮放、平移與重設。

選擇 **`B2A`（PCS → 裝置）表**時，網格下方會出現**各著色劑的灰階墨量覆蓋影像**——即各色墨的分色版，越暗表示該墨量越多。由於區段預設開啟的是 `A2B` 表（其輸出為 L\*a\*b\*，而非墨量），區段頂端會有提示引導您查看這些影像。對於**n 色 (nCLR) 輸出**——5、6 或 7 色——由於沒有簡單的彩色預覽，主影像會**經由設定檔的正向 `A2B` 進行色彩管理**，因此仍能以真實色彩呈現，而非單通道的灰階。

#### 色域影像 {#gamut-image src=92f58c0f}

色域標籤的色域內／色域外對應圖：PCS 顏色可再現處為中性色，落在裝置色域外處為紅色。僅在設定檔帶有 `gamt` 標籤時出現。

### 3.5 XML {#3-5-xml src=dfd43c4e}

將設定檔轉換為 XML（透過 IccLibXML，與 iccDEV `iccToXml` 命令列工具使用的寫入器相同），並在具語法醒目標示的 CodeMirror 編輯器中顯示。編輯 XML 後按**轉換為 ICC**，即可往返轉回二進位檔；檢視器會重新驗證，「設定檔」分頁工具列上的**儲存 ICC 設定檔**按鈕則可下載結果。

當編輯器文字與上次轉換器輸出不同時，會顯示**未套用修改**指示，讓您一眼看出編輯內容是否已套用。若轉換失敗，IccLibXML 的剖析錯誤會顯示在編輯器上方，並指出出錯的行／欄。

### 3.6 JSON {#3-6-json src=59c3f2e5}

與 XML 分頁的概念相同，但使用驗證器包裝層（`json-wrapper.cpp`）所產生的設定檔 JSON 表示法。編輯、按**轉換為 ICC**、儲存。JSON 形式較精簡，也較容易以程式處理；若您用過 iccDEV 命令列工具，XML 形式會比較熟悉。

## 4. 「連結」分頁 {#4-combine-tab src=735d6198}

profiletool 會將所有已載入的設定檔保存在左側的**設定檔集區**中。頂端有五個分頁——**設定檔**（即上述的單一設定檔檢視器）、**比較**、**連結**、**光譜**與 **HDR**。**連結**分頁用於將設定檔串接起來並加以運用：建立 **DeviceLink**、透過鏈條**轉換影像**，或**轉換色彩資料集**。

### 4.1 建立鏈條 {#4-1-building-a-chain src=83ab772c}

將一或多個設定檔從集區拖入「連結」卡片，即可依序加入鏈條。鏈條是**垂直堆疊**：來源在最上方，終點在最下方。每個設定檔提供**一個轉換**，工具會顯示進出該轉換的色彩空間（例如 `RGB → Lab`），並在各階段之間的連線上標示**銜接空間**。引擎會即時驗證整條鏈，並回報端到端的流向（例如 *鏈條：RGB → CMYK*），或逐階段說明在何處無法銜接。

- **重新排序**：拖曳某階段的握把（`⠿`）或使用 ▲ / ▼ 按鈕；按 × 可移除。
- **翻轉方向**：首個轉換的 ⇅ 按鈕會反轉鏈條方向，並連帶影響後續各階段。
- **轉換意圖**：以 *演算意圖（全部）* 為整條鏈選擇一種，或以各階段自己的清單方塊個別覆寫。將游標停在任一控制項上，可查看所選意圖的說明。除了四種基本意圖之外，帶有所需表格的設定檔還提供 *no D2Bx/B2Dx* 與 *+ BPC*（黑點補償）變體。

<div class="note">
<strong>鏈條中的 HDR ColorSpace 設定檔。</strong>ICC.1 HDR ColorSpace 設定檔沒有 TRC 標籤——第 8.7 條並未為 ColorSpace 設定檔定義此類標籤——因此經由它的轉換會使用其 <code>AToB0Tag</code>。該表即第 8.7.1.5 條要求、供不具 HDR 處理能力之軟體使用的 HDR&#8594;SDR 算繪。當鏈條中含有 HDR ColorSpace 設定檔時，卡片會加以說明：您產生的 DeviceLink、影像或資料反映的是該 SDR 回退，而非設定檔的 HDR 行為。
</div>

### 4.2 產生 DeviceLink {#4-2-make-devicelink src=2cb72a0d}

將整條鏈烘焙成單一的 **DeviceLink** 設定檔（iccDEV `iccApplyToLink` 的瀏覽器內移植版）。為它命名並按**產生 DeviceLink**；結果會像其他設定檔一樣加入集區與「連結」累積區，可在「設定檔」分頁中檢視，或在另一條鏈中重複使用。

### 4.3 轉換影像 {#4-3-transform-image src=461fcd83}

將一張點陣影像（TIFF、PNG 或 JPEG）拖入影像欄位，按**轉換影像**即可讓它通過鏈條（`iccApplyProfiles` 的瀏覽器內移植版）。影像會先經過只讀取檔頭的檢測——其色彩空間必須與鏈條的輸入相符。結果會**直接下載**；影像絕不會存入集區。

載入有效的影像後，會出現**影像輸出選項**面板，其中的輸出設定對應 `iccApplyProfiles` 命令列工具：

- **編碼**——*與來源相同*、8 位元、16 位元或**浮點（32 位元）**。
- **壓縮**——無、**LZW** 或 **ZIP**（Deflate）。
- **平面格式**——**交錯**（chunky）或**分離**的色版平面。
- **CMM 內插**——**四面體**或**線性**。
- **內嵌 ICC**——在輸出中標記鏈條的最後一個（輸出空間）設定檔。

預設會將 RGB/灰階輸出存為 PNG；選擇僅 TIFF 支援的選項（浮點、LZW/ZIP 或分離平面）時，容器會切換為 TIFF。

<div class="note">
<strong>內嵌設定檔：</strong>若拖入的影像本身帶有內嵌 ICC 設定檔，會出現橫幅讓您<strong>擷取</strong>它——只需按一下，該設定檔就會加入集區，並放在鏈條的開頭（作為來源空間）。
</div>

### 4.4 轉換資料 {#4-4-transform-data src=96934eec}

將色彩資料集（CGATS/IT8、CSV、CxF 或 JSON）拖入資料欄位，按**轉換資料**即可讓每個色塊通過鏈條（相當於 `iccApplyNamedCmm`）。工具會讀取資料集中的資料種類（裝置／Lab／XYZ／光譜），並提供鏈條輸入所需的那一種；**光譜**輸入會使用 iccDEV 的標準計算器、依您選擇的**觀察者**與**光源**轉換為比色值。重複的色塊可加以篩選（中位數或平均值）。結果會在表格中開啟，可**儲存**為 CSV。

### 4.5 觀察者轉換 {#4-5-observer-change src=738ba4d4}

「連結」分頁有**兩張**產生器卡片。在「連結管線」上方的 **觀察者轉換**卡片，可由一個 V5 RGB 顯示器設定檔加上一個 V5 觀察者 (PCC) 設定檔，建立 v4.3 矩陣/TRC 顯示器設定檔。將兩者都拖到卡片上——它們會依設定檔類別自動分配到 **V5 RGB 顯示器**與 **V5 觀察者 (PCC)** 欄位——然後按**建立 V4 顯示器設定檔**、為其命名，再按**建立**。結果會加入集區與此分頁。兩者皆非的設定檔會被忽略並顯示警告。

### 4.6 「比較」與「光譜」分頁 {#4-6-compare-and-spectral-tabs src=b934d7e3}

**比較**分頁會疊加顯示集區中兩個或以上設定檔的色域邊界——一個 3D 外殼加上一個 2D 明度切片——以便看出它們的差異。當設定檔為 HDR ColorSpace 設定檔時，**顯示 SDR 回退**說明會解釋：每個色域都是由 `AToB0Tag` 的 SDR 算繪建構而成，而非取自設定檔的 HDR 範圍，因為後者無法在有界的 PCS 中繪出。**光譜**分頁會將一組單通道光譜影像（依通道順序拖入）組裝成一個多通道 TIFF（`iccSpecSepToTiff`）。

## 5. 往返編輯 {#5-round-trip-editing src=595f380b}

XML 與 JSON 分頁都能將設定檔寫回 ICC 二進位檔。典型的工作流程：

1. **載入** ICC 設定檔。
2. 開啟 **XML** 或 **JSON** 分頁。按**轉換為 XML**／**轉換為 JSON** 以填入編輯器。
3. 在頁面內的編輯器中**編輯**。工具列旁會出現未儲存修改的指示。
4. 按**轉換為 ICC**。包裝層會建立新的設定檔、重新執行驗證，並更新「標頭」「標籤」「驗證」分頁。
5. 「設定檔」分頁工具列中的檔名旁會出現 **● 已修改 — 尚未儲存** 標記。
6. 按**儲存 ICC 設定檔**。編輯後的位元組會下載為 `<original>-edited.icc`。

兩個編輯器彼此獨立——先編輯 XML 再編輯 JSON，並不會混合兩條路徑。儲存的是最近一次產生的 ICC 位元組。

<div class="note">
<strong>注意：</strong>轉換的保真度取決於 IccLibXML／JSON 包裝層對各標籤類型的支援程度。若某標籤類型無法表示，往返後將會遺失細節；請在轉換回 ICC 後查看「驗證」分頁，確認一切仍能正常剖析。
</div>

「標籤」分頁會醒目標示任何位元組與原始載入時不同的標籤，方便您看出編輯改變了哪些內容。

## 6. 從 chardata 啟動 {#6-launching-from-chardata src=b39a6805}

在 **chardata** 中載入 ICC 設定檔後，按**顯示檔案**（Display File）開啟頁面內的檢視器，再按**開啟編輯器**（Launch editor）。此時會開啟一個新分頁，網址中帶有 `?source=chardata`。

交接完全在瀏覽器內進行：

1. profiletool 開啟後偵測到 `?source=chardata`，透過 `postMessage` 將 `{type:'profiletool:ready'}` 傳送給 `window.opener`。
2. chardata 回覆 `{type:'profiletool:load', filename, bytes}`。
3. profiletool 接收位元組（先依允許清單驗證傳送端的來源，並確認大小不超過 256 MB 上限），執行驗證並顯示設定檔。

不需上傳，也不經伺服器往返。此流程是單向的——在此所做的編輯需按**儲存 ICC 設定檔**另行儲存，不會傳回 chardata。

## 7. 以 URL 啟動 {#7-launching-with-a-url src=f9a8d871}

您可以使用 **URL 片段**（`#` 之後的部分），以一個指定要載入之設定檔——以及要開啟之分頁——的連結來開啟本工具：

```
https://chardata.colourbill.com/profiletool#url=<profile-url>&tab=<tab>
```

兩個參數皆為選用：

- **`url=`**——下載設定檔的網址。位元組會在您的瀏覽器中下載，接著經過與本機檔案完全相同的處理路徑：`acsp` 標頭檢查、完整的 `ValidateIccProfile`、256 MB 大小上限，以及針對無法剖析之設定檔的盡力而為後備處理。不會上傳任何內容——下載的位元組只會送入驗證器，絕不會再傳送出去。
- **`tab=`**——設定檔載入後要開啟哪個檢視。

完整範例：

```
https://chardata.colourbill.com/profiletool#url=https://example.org/profiles/sRGB.icc&tab=VAL
```

<div class="note">
<strong>為什麼用片段而不用查詢字串？</strong><code>#</code> 之後的部分絕不會傳送到網頁伺服器，因此您所檢視之設定檔的網址只會留在您自己的電腦上。
</div>

### 分頁名稱 {#tab-names src=d3a4dbae}

`tab=` 接受兩種可互換、不分大小寫的命名方式。建議使用**簡短**代碼：

| 檢視 | 簡短代碼 | 完整名稱 |
|---|---|---|
| 標頭 | `HEADER` | `Header` |
| 標籤 | `TAGS` | `Tags` |
| 驗證 | `VAL` | `Validation` |
| 分析 | `ANALYSIS` | `Analysis` |
| XML | `XML` | `XML` |
| JSON | `JSON` | `JSON` |

完整名稱是英文介面中的分頁標籤去除空格後的形式。即使畫面上的標籤更名，兩種命名方式都會維持不變，因此既有的連結仍可繼續使用。「驗證」分頁也接受舊版代碼 `PAWG`（其舊標籤為「Profile Assessment WG」）。無法辨識的 `tab=` 值會被忽略，並開啟「標頭」檢視。

<div class="note">
<strong><code>url=</code> 的要求：</strong>設定檔必須透過 <strong>HTTPS</strong> 提供，且託管伺服器必須允許跨來源讀取（寬鬆的 <code>Access-Control-Allow-Origin</code> / CORS 標頭）。缺少任一條件時，瀏覽器會封鎖下載，工具則會顯示擷取錯誤。若設定檔網址本身包含 <code>&</code> 或 <code>#</code>（即帶有自己的查詢字串），請對整個 <code>url=</code> 值進行百分比編碼，以免這些字元提前結束片段。
</div>

## 8. 行動裝置 {#8-mobile src=cb948e3c}

在寬度小於 700 px 的螢幕上：

- 「設定」面板會收合為從右側滑入的抽屜。
- 右上角的 **⚙** 浮動按鈕可開啟／關閉「設定」。
- ⚙ 下方的 **?** 按鈕會以滑入窗格開啟本指南。
- **✉** 按鈕會在新的瀏覽器分頁中開啟聯絡表單。
- 點選變暗的背景即可關閉已開啟的抽屜。
- 標籤表格會從寬格線重新排列為堆疊卡片，讓每一欄都不需水平捲動即可閱讀；標籤仍可就地展開。
- **以觸控取代拖放。**iOS 不支援拖放，因此無法將設定檔從集區拖到分頁上。請改為**點選設定檔以選取，再點選您要放入的分頁**——效果與拖曳相同。使用觸控螢幕時，集區會顯示這項提示。
- **在 iPhone 與 iPad 上，檔案選擇器會列出所有檔案。**iOS 會依它認得的類型比對檔案類型篩選條件，而它不認得 `.icc`、`.icm`、`.cube` 或 `.exr`，因此一旦篩選，正好會讓您要開啟的檔案變成灰色無法選取。請依名稱選取設定檔；任何不是設定檔的檔案，在載入後仍會被拒絕並附上原因。

所有功能皆可使用；版面會配合較小的螢幕調整。

## 9. 限制與安全性 {#9-limits-and-security src=ce1e9474}

profiletool 在初次載入頁面後不會發出任何網路請求。驗證器、XML 轉換器、JSON 轉換器與影像編解碼器，全都是由 C++ 原始碼編譯而成的 WebAssembly，完全在用戶端執行。HDR 分頁透過本機物件 URL 顯示拖入的影像，因此影像絕不會離開分頁。**識別顯示器**是向瀏覽器（而非伺服器）詢問視窗位於哪台顯示器上。

| 限制 | 適用位置 | 說明 |
|---|---|---|
| **256 MB** | postMessage／檔案載入 | 拒絕載入任何更大的內容；防止惡意的開啟端耗盡堆積記憶體 |
| **32 MB** | XML 與 JSON 轉換器 | JS 端防護（`MAX_XML_BYTES` / `MAX_JSON_BYTES`）與 C++ 包裝層（`kMaxXmlBytes` / `kMaxJsonBytes`）都會強制執行；C++ 端可獨立把關 |
| **XML 實體炸彈防護** | XML 轉換器 | 任何含有 `<!DOCTYPE` 或 `<!ENTITY`，或含有 NUL 位元組的 XML，都會在交給 libxml2 之前被拒絕。libxml2 本身的實體展開限制也同時生效，因此這是抵禦 billion-laughs 輸入的第二道防線 |
| **512 MB** | HDR 分頁檔案 | 在讀取檔案任何內容之前先檢查檔案大小；與影像編解碼器本身的 512 MB 輸入上限一致 |
| **4,000 萬像素**、**每位元組 64 像素** | Radiance HDR 解碼（HDR 分頁） | 兩者都在配置任何像素記憶體之前，依檔頭與檔案大小檢查；後者可拒絕利用重複標記的解壓縮炸彈 |
| **EXR 解碼預算** | OpenEXR 解碼 | 寬 × 高 × 通道數 × 4 位元組必須在 512 MB 以內，並在解碼器配置任何記憶體之前依檔頭檢查 |
| **HEIC/AVIF box 走訪** | 設定檔擷取 | 檢查 box 大小時不會溢位，巢狀深度上限為 8，設定檔上限為 64 MB（每個檔案的總計），項目關聯上限為 65 536 |
| **來源允許清單** | postMessage 啟動 | 只有同源以及 chardata 開發主機的來源可以傳送 `profiletool:load` 位元組 |
| **HTTPS + CORS** | `#url=` 啟動 | 以 URL 啟動的設定檔必須透過 HTTPS，從允許跨來源讀取的主機提供；下載的位元組只送入驗證器，絕不會再傳送出去 |

`#url=` 啟動（1.1.5 版新增）是工具在頁面載入後唯一會發出跨來源請求的情況：它將 Content-Security-Policy 的 `connect-src` 放寬為 `https:`，以便下載指定的設定檔。指令碼載入**並未**放寬——只放寬資料擷取。

若您需要檢視超出這些限制的設定檔，請從原始碼建置 iccDEV 並使用原生命令列工具——那些工具沒有 JS 端的上限。

### ICC.2 (iccMAX) 涵蓋範圍 {#icc-2-iccmax-coverage src=3d2b33e8}

**ICC.1** 與 **ICC.2** 設定檔皆受支援，但 ICC.2 的涵蓋範圍**尚不完整**。載入、標頭與標籤檢視、驗證、XML/JSON 往返以及轉換引擎都能處理 ICC.2；已知的缺口包括多段式 **ICS** 交換工作流程、套用轉換時選擇 V5 **子設定檔**，以及部分 ICC.2 設定檔的反向搜尋。使用不受支援之 ICC.2 結構的設定檔，會由「驗證」分頁回報，而不會被默默誤讀。

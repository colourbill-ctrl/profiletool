# ICC 配置文件工具 — 用户手册 {#icc-profile-tool-user-manual src=38bba1de}

**ICC 配置文件工具**（ICC Profile Tool，即 profiletool）是一款基于浏览器的工具，用于检查、验证和往返编辑 **ICC.1** 与 **ICC.2 (iccMAX)** 色彩配置文件。它完全在浏览器中运行——无需上传，无需安装——所用的是 [iccDEV](https://github.com/InternationalColorConsortium/iccDEV) 的 WebAssembly 构建版本，即 ICC 官方的 IccProfLib 演示实现。

**您可以：**

- **浏览标头** — 128 字节配置文件标头中的每个字段，均解码为易读的文字。
- **浏览标签目录** — 列出每个标签的签名、类型、字节偏移、大小和填充字节。点击任一标签即可展开完整的类型专属描述（与 iccDEV `wxProfileDump` 的 "Describe" 视图输出相同）；对于含有可视化数据的标签，还会显示内嵌的 **可视化**：色调响应曲线、色度图、CLUT 与色域图像、命名颜色散点图，以及单点 **转换求值器**。
- **验证** — 运行 ICC 配置文件评估工作组（Profile Assessment Working Group）的检查清单（安全性 / 符合性 / 质量），每项检查给出一个判定结果，并可按类别筛选。
- **往返编辑** — 将配置文件转换为 XML 或 JSON，在内置代码编辑器中编辑，再转换回 ICC 并重新验证。保存按钮会下载编辑后的二进制文件。
- **串联配置文件** — 在 **链接** 标签页中，将池中的配置文件拖入有序链条，然后把链条烘焙为 **DeviceLink**、用它 **转换图像**（可完全控制输出编码、压缩、平面布局和 ICC 嵌入），或 **转换色彩数据集**。
- **处理 HDR** — 按 ICC.1 HDR ColorSpace 配置文件规则（第 8.7.1 条）检查配置文件，读取其 cICP 代码点，并绘制任意显示余量下的自适应增益曲线。**HDR** 标签页可在您的显示器上显示一幅 HDR 图像，**设置 → 环境** 则报告当前浏览器和显示器的能力。
- **从 chardata 启动** — 将 [chardata](https://chardata.colourbill.com/) 中已加载的配置文件直接在此打开，字节数据通过 `postMessage` 在浏览器内传递。
- **通过 URL 启动** — 打开一个链接，让工具加载网上托管的配置文件，并可选择指定要打开的标签页（例如 `…/profiletool#url=…&tab=VAL`）。

所有处理均在客户端完成。配置文件的字节数据从不离开浏览器标签页。

<div class="note">
<strong>ICC.2 (iccMAX) 的支持尚不完整。</strong> ICC.2 配置文件可以像 ICC.1 配置文件一样加载、检查、验证和往返编辑——验证清单包含 iccMAX 专属检查，光谱 PCS 和多处理元素标签均可解码，转换引擎也基于完整的 iccMAX 栈构建。尚未覆盖的内容：多部分 <strong>ICS</strong>（交换色空间，Interchange Color Space）工作流、应用转换时选择 V5 <em>子配置文件</em>，以及部分 ICC.2 配置文件的反向搜索。较为特殊的 ICC.2 功能可能仍有欠缺，这些将在后续版本中逐步补齐。
</div>

<div class="note">
<strong>HDR ColorSpace 配置文件的支持依据的是草案。</strong> HDR 检查、<code>headroomAdaptiveGainCurveTag</code> 视图和 HDR 标签页实现的是 ICC.1 HDR 修订案的当前版本。该修订案尚未正式发布，因此在发布前细节可能会有变化。
</div>

## 1. 工作区 {#1-the-workspace src=4bc9350f}

profiletool 是一个 **多配置文件工作台**。窗口分为三部分：

- 左侧的 **配置文件** 窗格——即您已加载的所有内容组成的 *池*；
- 右侧的 **画布**，顶部有五个标签页——**配置文件**、**比较**、**链接**、**光谱**、**HDR**；
- 右边缘的 **设置** 侧栏（参见[设置面板](#2-settings-panel)）。

### 加载配置文件 {#loading-profiles src=2cd0f653}

可通过以下两种方式之一加载文件：

- 点击“配置文件”窗格顶部的 **加载配置文件**，选择一个或多个文件；或者
- 将文件 **拖放** 到“配置文件”窗格上。

您既可以加载 `.icc` / `.icm` 配置文件，*也*可以加载图像。拖入 **TIFF、PNG、JPEG、HEIC 或 AVIF** 文件时，工具会提取其中 **嵌入的 ICC 配置文件** 并加入池中。它只读取文件的元数据，从不读取像素。对于 HEIC 和 AVIF，工具会遍历文件的 box 结构，因此在任何浏览器中都可使用，包括无法显示这些格式的浏览器。**JPEG XL** 文件同样会被拒绝：其配置文件压缩在码流内部，而 profiletool 目前尚不能解压。与 HEIC 共用容器格式的视频和相机 RAW 文件（MP4、QuickTime、Canon CR3）不会被视为图像。**OpenEXR** 或 **Radiance HDR**（`.hdr`）文件会被拒绝并给出原因：这两种格式都没有存放 ICC 配置文件的位置。OpenEXR 通过色度坐标描述颜色，Radiance HDR 则通过可选的 `PRIMARIES` 标头行描述。如需 *查看* 图像，请使用 [HDR 标签页](#4-7-hdr-tab)。**＋ 从 .cube 新建** 按钮可从 `.cube` LUT 构建 DeviceLink。结果会加入池中并在 **配置文件** 标签页中打开；在您点击 **保存 ICC 配置文件** 之前不会下载任何内容。

只有当文件前 36 个字节中包含 `acsp` 签名，且能通过 IccProfLib 的 `ValidateIccProfile` 解析时，该配置文件才会被接受。未通过的文件会列在拒绝摘要中并注明具体原因；其字节数据不会保留。

### 配置文件窗格 {#the-profiles-pane src=04750126}

已加载的配置文件按 **配置文件类别**（输入、显示、输出、DeviceLink、ColorSpace、抽象、命名颜色……）分组到可折叠的分区中。ICC.1 第 8.7.1 条定义的 **HDR ColorSpace 配置文件** 则单独列在顶部的分区中（它们属于 ColorSpace 类配置文件，因此从 ColorSpace 分区中单独提出），并按传递函数分为 **线性传递函数** 和 **非线性传递函数（PQ、HLG）** 两组，每行以徽标标示其传递函数。这一划分在 [HDR 标签页](#4-7-hdr-tab) 中很重要：只有线性传递函数的配置文件才能指定给 OpenEXR 或 Radiance HDR 图像。每行显示文件名，以及类别、色彩空间、版本和大小的徽标；只能部分解析的配置文件会被标记。使用 **A–Z** 按钮循环切换排序方式（加载顺序 → 升序 → 降序），点击行上的 **×** 将其移除，拖动窗格右边缘的手柄调整宽度——也可以将窗格完全收起。

单击选中一行；按住 Ctrl/Cmd 单击可切换选中状态，按住 Shift 单击可选择一个范围。**将行从池中拖到某个标签页上**，即可在该标签页中使用它们。

<div class="note">
<strong>池仅在当前会话中有效。</strong> 不会上传任何内容，也不会持久保存任何内容——您的文件系统才是永久存储。重新加载页面会清空池。
</div>

### 标签页 {#the-tabs src=034c9677}

| 标签页 | 功能 |
|---|---|
| **配置文件** | 检查 **一个** 配置文件——标头、标签、验证、分析、XML、JSON。在此拖入新的配置文件会替换当前配置文件。 |
| **比较** | 叠加显示 **两个或更多** 配置文件的色域。 |
| **链接** | 将配置文件串联成 DeviceLink，或通过它们转换图像 / 数据集。 |
| **光谱** | 将多幅单通道光谱图像组装成一个多通道 TIFF。 |
| **HDR** | 在您的显示器上显示 **一幅** HDR 图像，并提供 SDR ↔ HDR 控件。参见 [HDR 标签页](#4-7-hdr-tab)。 |

“光谱”和“HDR”标签页直接接收图像文件，而不是池中的配置文件。其他每个标签页各自保留一组配置文件，以可移除的标签片显示在标签栏下方，并在标签页上以计数徽标显示数量。加载的第一个配置文件会自动在 **配置文件** 标签页中打开；此后，请从池中拖到您需要的标签页上。直接将文件拖放到某个标签页上，可一步完成加载到池中 *并* 放置到该标签页上。

<div class="note">
<strong>大小限制：</strong>加载器会拒绝任何大于 256 MB 的文件。实际的配置文件通常远小于 10 MB；设置这一上限只是为了防止恶意拖放或 postMessage 耗尽标签页的 WASM 堆。
</div>

## 2. 设置面板 {#2-settings-panel src=3bf599d9}

点击屏幕右边缘的 **⚙** 按钮（在移动设备上为右上角的齿轮图标）即可打开设置。面板会滑出覆盖在内容上方，而不会改变内容的尺寸。

⚙ 下方还有两个按钮：

- **?** 在 **应用内** 打开本指南，以窗格形式从窗口侧面滑入。其标题栏中有搜索框——输入文字即可高亮匹配项，然后用 `Enter` / `Shift+Enter`（或 `˄` `˅` 按钮）逐个跳转；`Escape` 清除搜索，再按一次 `Escape` 关闭窗格。
- **✉** 在新的浏览器标签页中打开 colourbill.com 上的联系表单。

面板分为两组：**显示** 和 **环境**。拖动面板左边缘可调整其宽度（220–560 px）；宽度会被记住。

### 背景 {#background src=1450fe76}

在 **浅色**、**深色** 和 **系统**（跟随操作系统偏好）主题之间切换。所选设置会跨会话保留。在 **系统** 模式下，应用会监听 `prefers-color-scheme`，并在操作系统主题变化时自动切换；明确选择“浅色”或“深色”则会取消该监听。

### 数字格式 {#number-format src=af65622c}

选择数值在各配置文件视图中的显示方式——**十六进制** 或 **十进制**。

### 语言 {#language src=38c60535}

覆盖界面语言。**系统默认 (…)** 会检测浏览器的区域设置并使用最接近的受支持语言，括号中显示该语言的本地名称，以便您看出选中的是哪一种。翻译范围涵盖应用界面：配置文件窗格、标签页名称、链接、光谱和 HDR 工具、标签视图中的 HDR 增益曲线视图、设置面板（包括“环境”及其中的原因说明），以及本指南的界面部分。部分文字不会翻译：
- 由 IccProfLib 生成的文字——标签描述、验证消息、标头字段名——来自 C++ 库，保持英文。
- 浏览器标志的名称保持英文，以便与浏览器自身的标志页面一致。
- “环境”面板中的 **显示事件** 日志保持英文，以便原样粘贴到错误报告中。
- 本指南遵循同一设置，但其中的 HDR 章节除外：在 HDR 支持处于测试阶段、文字仍在修改期间，这些章节保持英文。自上次翻译更新以来英文原文有修订的章节也会以英文显示并附有说明，直到译文跟上为止。

支持的语言：English、Français、Deutsch、Italiano、Español、Português (PT)、Português (BR)、Svenska、中文（简体）、中文（繁體）、日本語、한국어。chardata 的设置面板提供相同的语言集，因此在一个应用中切换语言后，在另一个应用中也能获得一致的阅读体验。

### 环境 {#environment src=2eb1ea2c}

显示 **当前** 浏览器、平台和显示器的能力，以便在某种格式或 HDR 功能不可用时，您能看出原因。从上到下依次为：

- **摘要** — 浏览器和操作系统，以及显示器是否报告支持 HDR。
- **浏览器标志**（Chrome、Edge、Opera、Brave）— *Experimental Web Platform features* 是否已开启。该标志会启用 HDR 画布，并允许页面读取显示器的 HDR 余量。
  - 当已知该标志处于关闭状态时，此框会高亮显示。如果此浏览器没有可用的 WebGPU，它会被标为 **必需**，因为此时 HDR 画布是渲染 HDR 的唯一途径；否则标为 **可选**。
  - 检查配置文件从不需要它。
  - 网页无法打开或更改浏览器标志。请点击 **复制**，将地址粘贴到地址栏，把该标志设为 *Enabled*，然后重新启动浏览器。
- **显示器信息** — **HDR 显示器**、**广色域**（sRGB、Display P3 或 Rec. 2020）、**像素比**，以及当前使用的 **HDR 画布路径**（`float16-canvas`、`webgpu` 或无）。当您把窗口拖到这些属性不同的屏幕上时，它们会自动刷新。切换发生在窗口的大部分移到新屏幕上时。
- **识别显示器**（Chromium 系浏览器）— 请求权限以查看窗口位于哪台显示器上。获得许可后，即使在外观相同的显示器之间移动，面板也会刷新，并显示 **当前显示器** 的名称；在浏览器提供该信息时（开启上述标志的 Chrome）还会显示 **HDR 余量**，例如 *1.35 档（≈ SDR 白的 2.55 倍）*。如果您拒绝了该权限，请在网站设置中更改。
  - 余量是 SDR 白之上的空间，因此在笔记本电脑内置的 HDR 面板上，**调高亮度时余量会减小**（SDR 白变亮，而面板峰值不变），调低亮度时余量会增大。观看 HDR 内容时，请调低亮度。
  - 在 Windows 上，亮度改变后需等待几秒钟，待显示驱动报告后才会得到新值。当窗口移到另一块屏幕，或 Chrome 重新成为活动应用时，也会刷新。
- **显示事件** — 可折叠的日志，记录最近 20 次刷新及其触发原因。报告显示问题时很有用。
- **格式表** — 每种格式一行（ICC 配置文件、TIFF、PNG、JPEG、OpenEXR、Radiance HDR、AVIF、HEIC/HEIF、JPEG XL），回答三个问题：
  - **检查**：能否读取嵌入的配置文件？
  - **显示**：能否显示像素？
  - **HDR**：能否渲染高于白色的亮度？

  将鼠标悬停在某行上可查看 ✕ 的原因；无法显示的格式及其原因会列在表格下方。圆点标记的是由 profiletool 自行解码的格式，它们在所有浏览器中表现一致。除 JPEG XL（其配置文件压缩在码流内部）外，所有格式的 **检查** 一栏均为 ✓。

## 3. 配置文件视图 {#3-profile-views src=ccf59d34}

将配置文件从池中拖到 **配置文件** 标签页上即可检查它。该标签页会显示一个栏，其中包含文件名和 **保存 ICC 配置文件** 按钮（编辑后还会出现 *● 已修改 — 尚未保存* 标记），下方是查看器：标题栏（文件名 · 字节大小 · IccProfLib 版本 · 有效性徽标）以及它自己的标签栏。

徽标汇总了 **验证** 报告：没有检查失败或警告时显示绿色 **通过**，至少一项检查给出警告时显示琥珀色 **警告**，任一检查失败时显示红色 **失败**。

<div class="note">
<strong>部分解析的配置文件：</strong>如果配置文件损坏到验证器只能读取其结构，会出现警告横幅，且只有 <strong>标头</strong> 和 <strong>标签</strong> 标签页可用——验证、分析、XML 和 JSON 标签页会被隐藏，因为不得应用该配置文件。
</div>

### 3.1 标头 {#3-1-header src=45c71bd0}

一个两列表格，列出 ICC 配置文件 128 字节二进制标头中的每个字段。数值通过 IccProfLib 的 `CIccInfo` 解码为易读的文字（展开签名、格式化日期、转换定点数值）。**配置文件 ID**（标头中的 MD5 哈希值）显示在顶部的高亮条中。

### 3.2 标签 {#3-2-tags src=90f22730}

一个六列网格，列出配置文件标签目录中的每个标签：

| 列 | 含义 |
|---|---|
| `#` | 在目录中的位置（从 1 开始） |
| `Name` | 易读的完整名称（例如 `profileDescriptionTag`） |
| `ID` | 4 字符签名（例如 `desc`） |
| `Offset` | 相对于文件开头的字节偏移 |
| `Size` | 标签数据的字节大小 |
| `Pad` | 此标签与下一个标签之间的填充字节数 |

标签 **类型** 签名（例如 `descType`、`mft2`、`mAB`）与偏移和大小一起显示在展开后标签的顶部。

标签按偏移排序。**填充** 列按颜色区分——`Pad < 0`（标签重叠，不合规）显示为红色；`Pad > 3`（填充超出规范）显示为琥珀色。

**点击任一行** 即可就地展开（手风琴式——一次只展开一个标签）。展开的详情最后总是完整的类型专属描述——相当于运行 IccProfLib 的 `CIccTag::Describe(verbosity = 100)`。对于含有大型 CLUT 或曲线的标签（例如 `A2B0`、`B2A0`），描述中会包含每个网格单元或曲线点。

在该描述上方，含有可视化数据的标签会显示一个或多个 **内嵌可视化**，各自位于可折叠的分区中：

| 标签类型 | 可视化 |
|---|---|
| 色调曲线（`rTRC`/`gTRC`/`bTRC`/`kTRC`） | 色调响应曲线，与恒等线对照绘制；曲线表折叠在其下方。 |
| RGB 着色剂（`rXYZ`/`gXYZ`/`bXYZ`）和白点（`wtpt`） | CIE 1931 色度图，高亮显示相应的原色（或白点）；着色剂 / 白点数据显示在其下方。 |
| LUT 转换（`A2B0–3`、`B2A0–3`、`gamt`、`pre0–2`） | 输入端和输出端的色调曲线（叠加显示，按着色剂区分颜色，可通过图例开关曲线）；以图像形式显示的 CLUT 网格；**色域图像**（用于配置文件的 `gamutTag`，按颜色区分——中性 = 色域内，红色 = 色域外）；**求值器**（见下文）；以及折叠的原始数据表。 |
| 命名颜色 / 着色剂表（`ncl2`/`nmcl`/`clrt`/`clot`） | 在 CIELAB a\*b\*（以及 CIE xy）图上的颜色散点图；表格折叠在其下方。 |
| 与编码无关的代码点（`cicp`） | **代码点**：色度基色、传递特性、矩阵系数和全范围标志，均按 ITU-T H.273 的定义命名。H.273 未分配的值会被标记，非零的保留字节也会被标记。 |
| 自适应增益曲线（`headroomAdaptiveGainCurveTag`） | **指定显示余量下的增益**，当标签中存有替代图像时还有 **增益曲线**。参见下文 *HDR gain curves (HAGC)*。 |

<div class="note">
<strong>异常数据从不隐藏。</strong> 如果某条曲线或其他可视化元素未通过 IccProfLib 的验证——例如 gamma 退化为 0 的色调曲线——该分区仍会尽可能渲染，并显示 ⚠ 警告及库给出的确切原因，而不会悄悄省略图表。
</div>

#### 转换求值器 {#the-transform-evaluator src=c70f94b4}

对于 LUT 转换（`A2B*` / `B2A*` / 预览标签），**求值** 分区直接使用 IccProfLib（不借助外部色彩引擎），将该标签的转换应用于您提供的单个颜色。方向由标签决定（`A2B*` 为设备 → PCS；`B2A*` 为 PCS → 设备），渲染意图也由标签隐含（`…0` 感知，`…1` 相对比色，`…2` 饱和度）。

- 输入可以是 **浮点值**（设备通道值，或以可读的 Lab/XYZ 单位表示的 PCS 值）；当标签含有 CLUT 时，也可以按 **网格点** 索引（网格上的节点位置）输入。
- 输出 **同时** 以内部归一化的 0–1 编码和可读单位（PCS 结果为 Lab/XYZ）显示。

色域标签（`gamt`）没有求值器——它是单通道的色域内 / 色域外映射，而不是可逆的转换；取而代之显示其色域图像。

### 3.3 验证 {#3-3-validation src=b72d6c69}

针对已加载的配置文件运行 **ICC 配置文件评估工作组**（Profile Assessment Working Group）检查清单，并以报告形式显示。这些检查来自 iccDEV 的 `iccPawgReport` 工具，它被编译为单独的 WebAssembly 模块，仅在您首次打开此标签页时才会获取。（标题栏中的有效性徽标也由同一报告驱动；通过 URL 启动时，可用 `VAL` 或旧代码 `PAWG` 打开此标签页。）

每项检查归入 **安全性**、**符合性** 或 **质量** 之一，并给出一个判定结果。含有 HDR 内容的配置文件还有第四组 **HDR**。其中第一项检查报告该配置文件是否为符合规范的 ICC.1 **HDR ColorSpace 配置文件**（第 8.7.1 条），其余各项检查该条所依赖的 HDR 元数据：

| 判定 | 含义 |
|---|---|
| **通过**（PASS） | 检查成功 |
| **警告**（WARN） | 不致命但值得复查的问题 |
| **失败**（FAIL） | 配置文件不满足该检查 |
| **缺口**（GAP） | 该检查无法完整评估（例如尚未实现） |
| **不适用**（N/A） | 该检查不适用于此配置文件 |
| **未运行**（NOT RUN） | 该检查被跳过 |

顶部的汇总行以彩色标记统计每种判定的数量。**点击标记即可筛选** 下方的报告——蓝色光晕标示当前显示的类别，数量为零的标记处于非活动状态。例如，关闭 **PASS** 和 **N/A**，即可只关注警告和失败项。

### 3.4 分析 {#3-4-analysis src=9478bc94}

根据配置文件的色彩转换得出的整体质量分析——由专用的 WebAssembly 模块（iccDEV 可视化引擎）计算，该模块仅在您首次打开此标签页时获取，结果以应用自身的风格绘制。

每项分析都是一个可折叠的分区，且 **所有分区初始均为折叠状态**。这是有意为之：每个分区都要对配置文件完整执行一遍转换计算，因此由您明确选择打开哪一个，而不是在切换标签页时同时启动六项分析。结果会被缓存，因此重新打开分区是即时的。不适用于已加载配置文件的分区会改为显示简短的 *不适用* 说明（例如，矩阵 / TRC 显示器配置文件没有可供分析的设备↔PCS CLUT）。

#### 特性文件统计 {#profile-statistics src=f2d4f2db}

针对 **一个** 选定渲染意图的整体配置文件指标，由两个列表框和一个复选框控制：

- **渲染意图** — 感知 / 相对比色 / 饱和度 / 绝对比色。
- **往返类型** — 要报告的精度指标（见下文）。
- **使用 MPE（颜色）标签** — 关闭 = 比色查找表；开启 = 多处理元素 / 颜色标签。它对色域内概览不起作用，在该模式下被禁用。

表格显示 **色域体积**（单位为 ΔE\*ab³，即设备 → PCS 的 `A2B` 转换所包围的体积，通过将边界体素化并统计被包围的单元计算），以及所选往返的 **最小值 / 平均值 / 标准差 / P90 / 最大值** ΔE\*ab。下方是 ΔE 分布直方图——相对频率柱状图加累积频率曲线——以及误差最大处的 `L, a, b`；对于 PRMG，还会显示该配置文件是否隐含感知参考媒介色域。

四种往返类型：

- **色域内概览 (RT0)** — 将设备值网格转到 PCS、转回设备，再转到 PCS；在两次 PCS 结果之间测量 ΔE\*ab。这是快速的色域内稳定性检查。
- **反演 + 色域 (RT1)** — 每个设备颜色的 PCS 值，与其经过一次 Lab → 设备 → Lab 往返后的 PCS 值之间的 ΔE\*ab。它同时反映反演精度 *和* 色域映射。
- **可重现性 (RT2)** — 第一次与第二次往返之间的 ΔE\*ab：反映重复往返的稳定程度，与第一次往返的色域裁剪无关。
- **PRMG 互操作性** — 对感知参考媒介色域内的 PCS 颜色做一次往返；ΔE 分布反映跨配置文件的互操作性。

直方图下方的 **按明度的往返 ΔE** 回答了汇总数字无法回答的问题：反演在色调范围的 *哪个位置* 出现困难，问题又 *深入色域多远*。

它对 32 个明度级别进行采样。在每个级别上，先在 **色域边界上** 取 64 个点，然后将它们分别向中性轴收缩到其彩度的 80 %、50 % 和 20 % 再各取一遍——共 8,192 个点，每个点单独绘制，各级别之间以虚线分隔。

请逐段阅读。在一段之内，点从左侧的色域表面排列到右侧的中性点，因此误差应在这一段内 **逐渐下降**：靠近边界的颜色最难反演，靠近中性的颜色最容易。如果某一段的误差一直到中性都居高不下，说明该配置文件在这一明度上有问题。最高的尖峰标示的是色域边界本身反演效果最差的明度级别。

每个种子点按构造都位于色域内，因此您看到的是真实的 `B2A`/`A2B` 不一致，而不是颜色因无法达到而被裁剪。请注意，此图有其 **自己的** 采样方式——有意偏重色域边界——因此其平均值和最大值会高于上表，且不可与上表直接比较。它跟随渲染意图，但不跟随往返类型。

缺少某项指标所需设备↔PCS 转换的配置文件会显示 *不适用* 说明；设备色彩空间太大而无法采样时，会报告为已跳过，而不是报错。

#### 极值比色 {#extrema-colorimetry src=be6c9597}

配置文件再现范围的两端——印刷操作员通常最先查看的数字。

- **白点** — **零着色剂** 的颜色，即裸露承印物的颜色。
- **黑点** — 将 PCS 黑（L\*=0，a\*=b\*=0）送入所选的 `B2A` 表，得到配置文件为黑色 *选择* 的墨量，再将该墨量经 `A2B1` 读回而求得。
- 两者都以 **相对** 和 **绝对** 比色显示。绝对比色显示承印物本身的颜色（偏蓝的白纸读数约为 L\* 95、b\* −4）；相对比色则将其重新参照到理想白。如果两列完全相同，这是正常的——只是媒体白恰好与光源一致。没有媒体白点标签的配置文件只显示相对值。
- **黑点处的墨量** 和 **TAC** — 该黑色下每个通道的墨量及其总和：总面积覆盖率，即墨量限制值。

由于每个 `B2A` 表都为黑色选择自己的墨量，黑点在不同意图之间确实不同——因此提供了渲染意图选择器。

其下方是 **实地与最大彩度**：对每个油墨角点（C、M、Y、R、G、B 和 K），给出它在色相 / 彩度 / 明度上的落点，以及从裸露承印物到该点的途中找到的彩度最高的点。这些行通过 `A2B1` 测量，因此 **不随意图选择器变化**。在表现良好的配置文件上，这两行一致。当最大彩度在实地 *之前* 就已达到时，该行会被标记：超过该点后，增加的墨量不再提高彩度，只会使颜色变暗。

**仅适用于输出（打印机）配置文件** — 该分析假定零着色剂即裸露承印物。按色相的表格还要求 **CMYK 或 CMY** 设备色彩空间：n 色（nCLR）配置文件的通道可按任意顺序命名，因此无法确定哪个通道是“青”，表格会如实报告这一点，而不是猜测。

#### 中性轴墨量 {#neutral-axis-inking src=aa5449e4}

沿中性轴（a\*=b\*=0）从白（L\*=100）扫描到黑（L\*=0），通过配置文件的 `B2A`（PCS → 设备）表，绘制配置文件沿途施加的每种设备着色剂的量——即经典的 GCR / 中性灰构成曲线。每个设备通道一条曲线，按着色剂区分颜色。

在分色曲线之上还绘制了另一条曲线：

- **L\* 输出（色调）** — 色调响应：中性轴经过配置文件往返后实际落在的明度。从其形状可读出两点。低于对角线的下凹意味着灰色比要求的更暗。更有用的是，曲线 **在配置文件可达到的最暗明度处变平**——这个平台 *就是* 媒体黑点，它应与上文的极值比色分区一致。

**仅适用于输出（打印机）配置文件**；其他类别的配置文件会显示说明。

#### 暗调中的用墨 {#ink-usage-in-shadows src=e62016b7}

在一个恒定且刻意选取的较暗明度上，沿 a\*b\* 平面上的四条直线路径——0°、45°、90° 和 135°——送入所选的 `B2A` 表，并为每条路径绘制得到的分色结果。

由于路径上的每个样本都具有相同的 L\*，某种着色剂出现的任何突变或反转都仅源于色相和彩度的处理。这是暗调色域映射瑕疵的特征，在印刷中会表现为暗部的条纹或突然的颜色偏移。路径从色域外很远处出发，穿过色域，再从另一侧穿出，因此您还能看到配置文件从哪里开始截断。

明度平面自动选取：位于配置文件蓝色角点与 C、M、Y、R、G 中最暗者之间的中点。对于感知和饱和度表，明度会先从媒体黑点拉伸到 PCS 黑——这些表期望黑色位于该处——该分区会同时报告补偿后的平面和原始平面。

**仅适用于输出（打印机）配置文件**，且与上文按色相的表格有相同的 CMYK/CMY 限制（平面由油墨角点推导）。

#### 经中性轴的原色墨路 {#primary-inking-paths-through-neutral src=cb510c25}

三条路径——青→红、品红→绿、黄→蓝——每条从一个原色角点出发，在两个端点的中点明度处 **经过中性轴**，到达相对的角点，送入所选的 `B2A` 表并以分色形式绘制。

这是“暗调中的用墨”在色域内的对应分析。在那里，路径有意延伸到色域外以暴露色域映射瑕疵；而在这里，**每个样本按构造都位于色域内**——两个端点都是配置文件自身的原色，转折点位于中性轴上。因此，着色剂沿这些路径出现的台阶、拐折或反转不能归咎于色域裁剪：它是 CLUT 平滑性缺陷。中性转折点位于每幅图的中点，在那里您应看到平衡的中性灰构成。

对于感知和饱和度表，明度会针对该意图进行黑场补偿，与“暗调中的用墨”完全相同。

**仅适用于输出（打印机）配置文件**，且有相同的 CMYK/CMY 限制（角点与按色相的表格来源相同）。

#### 墨量统计 {#ink-usage-statistics src=191fd7cd}

配置文件施加的每种着色剂的量，以平均覆盖率和 **占总量的比例** 表示——即分色的耗墨特征。

表格沿中性轴对每种着色剂求和，并报告其平均覆盖率及其在全部用墨中所占的百分比。占比一栏最具诊断价值：它是配置文件中性灰构成的指纹（偏重青色的灰平衡与偏重黑色的灰平衡读数不同），且与采样数量无关。

第二个表格——**所有色域边界上及色域内颜色** 的用墨——标为 *待定*：它需要尚未构建的色域边界构造。

**仅适用于输出（打印机）配置文件。**

#### CLUT 图像 {#clut-image src=a3fec568}

设备↔PCS 转换的颜色查找表，平铺成一幅图像，并可选择要查看哪个渲染意图表（`A2B0`–`A2B3`、`B2A0`–`B2A3` 以及预览表）。可用于一眼发现表中的结构性损坏。使用画布上的控件进行缩放、平移和复位。

选择 **`B2A`（PCS → 设备）表** 时，网格下方会出现 **每种着色剂的灰度墨量覆盖图像**——即各油墨的分色图，越暗表示该油墨越多。由于该分区打开时显示的是 `A2B` 表（其输出为 L\*a\*b\*，而非墨量），分区顶部会有提示引导您查看这些图像。对于 **n 色（nCLR）输出**——5、6 或 7 色——由于没有简单的彩色预览，主图像会 **通过配置文件的正向 `A2B` 进行色彩管理**，从而仍以真实颜色呈现，而不是单通道灰度。

#### 色域图像 {#gamut-image src=92f58c0f}

色域标签的色域内 / 色域外映射：PCS 颜色可再现处显示为中性，超出设备色域处显示为红色。仅当配置文件含有 `gamt` 标签时才会出现。

### 3.5 XML {#3-5-xml src=dfd43c4e}

将配置文件转换为 XML（通过 IccLibXML，即 iccDEV `iccToXml` 命令行工具所用的同一写入器），并在带语法高亮的 CodeMirror 编辑器中显示。编辑 XML 后点击 **转换为 ICC** 即可往返转换回二进制；查看器会重新验证，配置文件标签页栏中的 **保存 ICC 配置文件** 按钮会下载结果。

当编辑器文本与上次转换器输出不同时，会显示 **未保存** 指示，让您一眼看出编辑是否已应用。如果转换失败，IccLibXML 的解析错误会显示在编辑器上方，并注明出错的行 / 列。

### 3.6 JSON {#3-6-json src=59c3f2e5}

与 XML 标签页思路相同，但使用由验证器封装层（`json-wrapper.cpp`）生成的配置文件 JSON 表示。编辑后点击 **转换为 ICC** 并保存。JSON 形式更紧凑，也更便于编写脚本处理；如果您用过 iccDEV 命令行工具，XML 形式会更熟悉。

## 4. 链接标签页 {#4-combine-tab src=735d6198}

profiletool 将每个已加载的配置文件保存在左侧的 **配置文件池** 中。顶部有五个标签页——**配置文件**（即上文所述的单配置文件查看器）、**比较**、**链接**、**光谱** 和 **HDR**。**链接** 标签页用于将配置文件串联起来并加以使用：构建 **DeviceLink**、通过链条 **转换图像** 或 **转换色彩数据集**。

### 4.1 构建链条 {#4-1-building-a-chain src=83ab772c}

将一个或多个配置文件从池中拖入“链接”卡片，即可按顺序将它们加入链条。链条是一个 **纵向堆叠**：源在顶部，目标在底部。每个配置文件贡献 **一个转换**，工具会显示进入和离开该转换的色彩空间（例如 `RGB → Lab`），并在各阶段之间的连线上标注 **连接空间**。引擎会实时验证整个链条，并报告端到端的流向（例如 *链条：RGB → CMYK*），或逐阶段说明在何处无法衔接。

- **重新排序**：拖动阶段的抓手（`⠿`）或使用 ▲ / ▼ 按钮；点击 × 移除阶段。
- **翻转方向** — 首个转换的 ⇅ 按钮会反转链条方向，并依次影响后续各阶段。
- **渲染意图** — 可通过 *渲染意图（全部）* 为整个链条选择一种，也可用各阶段自己的列表框单独覆盖。将鼠标悬停在任一控件上可查看所选意图的说明。除四种基本意图外，含有所需表格的配置文件还提供 *no D2Bx/B2Dx* 和 *+ BPC*（黑场补偿）变体。

<div class="note">
<strong>链中包含 HDR ColorSpace 配置文件。</strong> ICC.1 HDR ColorSpace 配置文件没有 TRC 标签——第 8.7 条没有为 ColorSpace 配置文件定义 TRC 标签——因此经过它的转换使用其 <code>AToB0Tag</code>。该表即第 8.7.1.5 条为不具备 HDR 处理能力的软件所要求的 HDR&#8594;SDR 渲染。当链条中包含 HDR ColorSpace 配置文件时，卡片会对此加以说明：您生成的 DeviceLink、图像或数据反映的是这一 SDR 回退，而不是配置文件的 HDR 行为。
</div>

### 4.2 生成 DeviceLink {#4-2-make-devicelink src=2cb72a0d}

将整个链条烘焙为单个 **DeviceLink** 配置文件（iccDEV `iccApplyToLink` 的浏览器内移植）。为其命名并点击 **生成 DeviceLink**；结果会像其他配置文件一样进入池和“链接”累积区，可在配置文件标签页中检查，或在另一个链条中复用。

### 4.3 转换图像 {#4-3-transform-image src=461fcd83}

将一幅栅格图像（TIFF、PNG 或 JPEG）拖入图像槽，点击 **转换图像** 即可让它通过链条（`iccApplyProfiles` 的浏览器内移植）。图像会先经过仅读取标头的探测验证——其色彩空间必须与链条的输入匹配。结果会 **下载**；图像从不存入池中。

加载有效图像后，会出现 **图像输出选项** 面板，其中的目标参数与 `iccApplyProfiles` 命令行工具一一对应：

- **编码** — *与源相同*、8 位、16 位或 **浮点（32 位）**。
- **压缩** — 无、**LZW** 或 **ZIP**（Deflate）。
- **平面格式** — **交错**（chunky）或 **分离** 平面。
- **CMM 插值** — **四面体** 或 **线性**。
- **嵌入 ICC** — 在输出中标记链条的最后一个（输出空间）配置文件。

默认设置下，RGB/灰度输出保存为 PNG；选择仅 TIFF 支持的选项（浮点、LZW/ZIP 或分离平面）会将容器切换为 TIFF。

<div class="note">
<strong>嵌入的配置文件：</strong>如果拖入的图像带有自己嵌入的 ICC 配置文件，会出现横幅提示可将其 <strong>提取</strong>——一键即可将该配置文件加入池中，并放到链条开头（作为其源空间）。
</div>

### 4.4 转换数据 {#4-4-transform-data src=96934eec}

将色彩数据集（CGATS/IT8、CSV、CxF 或 JSON）拖入数据槽，点击 **转换数据** 即可让每个色块通过链条（相当于 `iccApplyNamedCmm`）。工具会读取数据集中包含的数据种类（设备 / Lab / XYZ / 光谱），并提供链条输入所需的那一种；**光谱** 输入会用 iccDEV 的标准计算器换算为色度值，所用的 **观察者** 和 **光源** 由您选择。可以过滤重复的色块（取中位数或平均值）。结果会在表格中打开，您可以将其 **保存** 为 CSV。

### 4.5 观察者变换 {#4-5-observer-change src=738ba4d4}

“链接”标签页包含 **两张** 生成器卡片。在“链接流水线”上方，**观察者变换** 卡片可由一个 V5 RGB 显示器配置文件加一个 V5 观察者（PCC）配置文件，构建 v4.3 矩阵 / TRC 显示器配置文件。将两者都拖到卡片上——它们会按配置文件类别自动分配到 **V5 RGB 显示器** 和 **V5 观察者 (PCC)** 槽中——然后点击 **创建 V4 显示器配置文件**，为其命名，再点击 **创建**。结果会加入池和此标签页。两者都不是的配置文件会被忽略并给出警告。

### 4.6 比较与光谱标签页 {#4-6-compare-and-spectral-tabs src=b934d7e3}

**比较** 标签页叠加显示池中两个或更多配置文件的色域边界——一个 3D 外壳加一个 2D 明度切片——以便看出它们的差异。当配置文件是 HDR ColorSpace 配置文件时，**显示 SDR 回退** 说明会解释：每个色域都是由 `AToB0Tag` 的 SDR 渲染构建的，而不是由配置文件的 HDR 范围构建，因为后者无法在有界的 PCS 中绘制。**光谱** 标签页将一组单通道光谱图像（按通道顺序拖入）组装成一个多通道 TIFF（`iccSpecSepToTiff`）。

## 5. 往返编辑 {#5-round-trip-editing src=595f380b}

XML 和 JSON 标签页都能将配置文件写回 ICC 二进制格式。典型工作流程：

1. **加载** 一个 ICC 配置文件。
2. 打开 **XML** 或 **JSON** 标签页。点击 **转换为 XML** / **转换为 JSON** 填充编辑器。
3. 在页面内的编辑器中 **编辑**。工具栏旁会出现未保存指示。
4. 点击 **转换为 ICC**。封装层会构建新的配置文件，重新运行验证，并更新标头 / 标签 / 验证标签页。
5. 配置文件标签页栏中的文件名旁会出现 **● 已修改 — 尚未保存** 标记。
6. 点击 **保存 ICC 配置文件**。编辑后的字节会以 `<original>-edited.icc` 的形式下载。

两个编辑器相互独立——先编辑 XML 再编辑 JSON 不会混合两条路径。保存的是最近一次生成的 ICC 字节。

<div class="note">
<strong>注意：</strong>转换的保真度取决于 IccLibXML / JSON 封装层对各标签类型的支持程度。如果某种标签类型无法表示，往返过程会丢失细节；转换回来后，请查看验证标签页，确认一切仍能正常解析。
</div>

标签视图会高亮显示字节与原始加载时不同的标签，便于看出您的编辑改动了什么。

## 6. 从 chardata 启动 {#6-launching-from-chardata src=b39a6805}

在 **chardata** 中加载 ICC 配置文件后，点击 **显示文件** 打开页面内查看器，然后点击 **打开编辑器**。此时会打开一个新标签页，URL 中带有 `?source=chardata`。

交接完全在浏览器内完成：

1. profiletool 打开后检测到 `?source=chardata`，并通过 `postMessage` 向 `window.opener` 发送 `{type:'profiletool:ready'}`。
2. chardata 回复 `{type:'profiletool:load', filename, bytes}`。
3. profiletool 接收字节数据（先根据允许列表验证发送方来源，并检查大小不超过 256 MB 上限），运行验证，然后显示配置文件。

无需上传，也没有服务器往返。数据流是单向的——在此所做的编辑需点击 **保存 ICC 配置文件** 保存，不会传回 chardata。

## 7. 通过 URL 启动 {#7-launching-with-a-url src=f9a8d871}

您可以通过一个链接打开工具，在链接中指定要加载的配置文件以及要打开的标签页，方法是使用 **URL 片段**（`#` 之后的部分）：

```
https://chardata.colourbill.com/profiletool#url=<profile-url>&tab=<tab>
```

两个参数都是可选的：

- **`url=`** — 获取配置文件的网址。字节数据在您的浏览器中下载，然后经过与本地文件完全相同的处理路径：`acsp` 标头检查、完整的 `ValidateIccProfile`、256 MB 大小上限，以及针对无法解析的配置文件的尽力回退。不会上传任何内容——获取的字节只供验证器使用，从不重新发送。
- **`tab=`** — 配置文件加载后要打开的视图。

完整示例：

```
https://chardata.colourbill.com/profiletool#url=https://example.org/profiles/sRGB.icc&tab=VAL
```

<div class="note">
<strong>为什么用片段而不用查询字符串？</strong> <code>#</code> 之后的部分从不会发送到 Web 服务器，因此您所检查的配置文件的地址只保留在您自己的计算机上。
</div>

### 标签页名称 {#tab-names src=d3a4dbae}

`tab=` 接受两种可互换、不区分大小写的命名方案。推荐使用 **短** 代码：

| 视图 | 短代码 | 长名称 |
|---|---|---|
| 标头 | `HEADER` | `Header` |
| 标签 | `TAGS` | `Tags` |
| 验证 | `VAL` | `Validation` |
| 分析 | `ANALYSIS` | `Analysis` |
| XML | `XML` | `XML` |
| JSON | `JSON` | `JSON` |

长名称是英文界面中的标签页名称去掉空格后的形式。即使界面上的名称被重命名，两种方案都会保持稳定，因此现有链接仍可使用。验证标签页还接受旧代码 `PAWG`（它以前的名称是“Profile Assessment WG”）。无法识别的 `tab=` 值会被忽略，并打开标头视图。

<div class="note">
<strong><code>url=</code> 的要求：</strong>配置文件必须通过 <strong>HTTPS</strong> 提供，且托管服务器必须允许跨源读取（宽松的 <code>Access-Control-Allow-Origin</code> / CORS 标头）。缺少任何一项，浏览器都会阻止下载，工具会显示获取错误。如果配置文件的 URL 本身包含 <code>&</code> 或 <code>#</code>（即它自己的查询字符串），请对整个 <code>url=</code> 值进行百分号编码，以免这些字符提前终止片段。
</div>

## 8. 移动设备 {#8-mobile src=cb948e3c}

在宽度小于 700 px 的屏幕上：

- 设置面板收起为从右侧滑入的抽屉。
- 右上角的 **⚙** 浮动按钮用于打开 / 关闭设置。
- ⚙ 下方的 **?** 按钮在滑入窗格中打开本指南。
- **✉** 按钮在新的浏览器标签页中打开联系表单。
- 点按变暗的背景可关闭已打开的抽屉。
- 标签表格会从宽网格重排为堆叠的卡片，因此无需横向滚动即可读到每一列；标签仍可就地展开。
- **以触控代替拖放。** iOS 不支持拖放，因此无法在其上将配置文件从池中拖到标签页上。请改为 **点按配置文件将其选中，然后点按目标标签页**——效果与拖放相同。使用触摸屏时，池中会显示这一提示。
- **在 iPhone 和 iPad 上，文件选择器会列出所有文件。** iOS 会将文件类型筛选条件与其已知的类型进行匹配，而它不认识 `.icc`、`.icm`、`.cube` 或 `.exr`，因此一旦筛选，恰恰会把您要打开的文件变灰。请按名称选择配置文件；任何不是配置文件的文件在加载后仍会被拒绝并给出原因。

所有功能均可使用；布局会适应较小的屏幕。

## 9. 限制与安全 {#9-limits-and-security src=ce1e9474}

profiletool 在初始页面加载后不会发出任何网络请求。验证器、XML 转换器、JSON 转换器和图像编解码器都是由 C++ 源代码编译而成的 WebAssembly，完全在客户端运行。HDR 标签页通过本地对象 URL 显示拖入的图像，因此图像从不离开标签页。**识别显示器** 询问的是浏览器而不是服务器，以确定窗口位于哪台显示器上。

| 限制 | 位置 | 说明 |
|---|---|---|
| **256 MB** | postMessage / 文件加载 | 拒绝加载更大的内容；防止恶意的打开方耗尽堆内存 |
| **32 MB** | XML 和 JSON 转换器 | JS 端检查（`MAX_XML_BYTES` / `MAX_JSON_BYTES`）和 C++ 封装层（`kMaxXmlBytes` / `kMaxJsonBytes`）都执行此限制；C++ 端独立生效 |
| **XML 实体炸弹防护** | XML 转换器 | 任何包含 `<!DOCTYPE` 或 `<!ENTITY`、或包含 NUL 字节的 XML，都会在交给 libxml2 之前被拒绝。libxml2 自身的实体扩展限制也处于启用状态，因此这是防御 billion-laughs 输入的第二道防线 |
| **512 MB** | HDR 标签页文件 | 在读取文件任何内容之前先检查其大小；与图像编解码器自身的 512 MB 输入上限一致 |
| **4000 万像素**、**每字节 64 像素** | Radiance HDR 解码（HDR 标签页） | 两者都在分配任何像素内存之前，根据标头和文件大小进行检查；后者用于拒绝重复标记式解压炸弹 |
| **EXR 解码预算** | OpenEXR 解码 | 宽 × 高 × 通道数 × 4 字节必须不超过 512 MB，在解码器分配任何内存之前根据标头检查 |
| **HEIC/AVIF box 遍历** | 配置文件提取 | 检查 box 大小时不会溢出，嵌套深度上限为 8，配置文件上限为 64 MB（每个文件的总计），项目关联上限为 65 536 |
| **来源允许列表** | postMessage 启动 | 只有同源和 chardata 开发主机的来源才能发送 `profiletool:load` 字节数据 |
| **HTTPS + CORS** | `#url=` 启动 | 通过 URL 启动的配置文件必须经 HTTPS、从允许跨源读取的主机提供；获取的字节只供验证器使用，从不重新发送 |

`#url=` 启动（1.1.5 版加入）是工具在页面加载后发出跨源请求的唯一情形：它将内容安全策略（Content-Security-Policy）的 `connect-src` 放宽到 `https:`，以便获取指定的配置文件。脚本加载 **并未** 放宽——只放宽了数据获取。

如需检查超出这些限制的配置文件，请从源代码构建 iccDEV 并使用原生命令行工具——它们没有 JS 端的上限。

### ICC.2 (iccMAX) 覆盖范围 {#icc-2-iccmax-coverage src=3d2b33e8}

**ICC.1** 和 **ICC.2** 配置文件均受支持，但 ICC.2 的覆盖 **尚不完整**。加载、标头和标签视图、验证、XML/JSON 往返以及转换引擎都能理解 ICC.2；已知的欠缺包括多部分 **ICS** 交换工作流、应用转换时选择 V5 **子配置文件**，以及部分 ICC.2 配置文件的反向搜索。使用了不受支持的 ICC.2 结构的配置文件会由验证标签页报告，而不会被悄悄误读。

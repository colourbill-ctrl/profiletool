ICC 配置文件工具 — 帮助

基于浏览器的 ICC.1 与 ICC.2 (iccMAX) 配置文件检查器、验证器和往返编辑器

ICC 配置文件工具（ICC Profile Tool，即 profiletool）是一款基于浏览器的工具，用于检查、验证和往返编辑 ICC.1 与 ICC.2 (iccMAX) 色彩配置文件。它完全在浏览器中运行——无需上传，无需安装——所用的是 iccDEV 的 WebAssembly 构建版本，即 ICC 官方的 IccProfLib 演示实现。

您可以：

  • 浏览标头 — 128 字节配置文件标头中的每个字段，均解码为易读的文字。
  • 浏览标签目录 — 列出每个标签的签名、类型、字节偏移、大小和填充字节。点击任一标签即可展开完整的类型专属描述（与 iccDEV wxProfileDump 的 "Describe" 视图输出相同）；对于含有可视化数据的标签，还会显示内嵌的 可视化：色调响应曲线、色度图、CLUT 与色域图像、命名颜色散点图，以及单点 转换求值器。
  • 验证 — 运行 ICC 配置文件评估工作组（Profile Assessment Working Group）的检查清单（安全性 / 符合性 / 质量），每项检查给出一个判定结果，并可按类别筛选。
  • 往返编辑 — 将配置文件转换为 XML 或 JSON，在内置代码编辑器中编辑，再转换回 ICC 并重新验证。保存按钮会下载编辑后的二进制文件。
  • 串联配置文件 — 在 链接 标签页中，将池中的配置文件拖入有序链条，然后把链条烘焙为 DeviceLink、用它 转换图像（可完全控制输出编码、压缩、平面布局和 ICC 嵌入），或 转换色彩数据集。
  • 处理 HDR — 按 ICC.1 HDR ColorSpace 配置文件规则（第 8.7.1 条）检查配置文件，读取其 cICP 代码点，并绘制任意显示余量下的自适应增益曲线。HDR 标签页可在您的显示器上显示一幅 HDR 图像，设置 → 环境 则报告当前浏览器和显示器的能力。
  • 从 chardata 启动 — 将 chardata 中已加载的配置文件直接在此打开，字节数据通过 postMessage 在浏览器内传递。
  • 通过 URL 启动 — 打开一个链接，让工具加载网上托管的配置文件，并可选择指定要打开的标签页（例如 …/profiletool#url=…&tab=VAL）。

所有处理均在客户端完成。配置文件的字节数据从不离开浏览器标签页。

ICC.2 (iccMAX) 的支持尚不完整。 ICC.2 配置文件可以像 ICC.1 配置文件一样加载、检查、验证和往返编辑——验证清单包含 iccMAX 专属检查，光谱 PCS 和多处理元素标签均可解码，转换引擎也基于完整的 iccMAX 栈构建。尚未覆盖的内容：多部分 ICS（交换色空间，Interchange Color Space）工作流、应用转换时选择 V5 子配置文件，以及部分 ICC.2 配置文件的反向搜索。较为特殊的 ICC.2 功能可能仍有欠缺，这些将在后续版本中逐步补齐。
HDR ColorSpace 配置文件的支持依据的是草案。 HDR 检查、headroomAdaptiveGainCurveTag 视图和 HDR 标签页实现的是 ICC.1 HDR 修订案的当前版本。该修订案尚未正式发布，因此在发布前细节可能会有变化。

1. 工作区

profiletool 是一个 多配置文件工作台。窗口分为三部分：

  • 左侧的 配置文件 窗格——即您已加载的所有内容组成的 池；
  • 右侧的 画布，顶部有五个标签页——配置文件、比较、链接、光谱、HDR；
  • 右边缘的 设置 侧栏（参见设置面板）。

加载配置文件

可通过以下两种方式之一加载文件：

  • 点击“配置文件”窗格顶部的 加载配置文件，选择一个或多个文件；或者
  • 将文件 拖放 到“配置文件”窗格上。

您既可以加载 .icc / .icm 配置文件，也可以加载图像。拖入 TIFF、PNG、JPEG、HEIC 或 AVIF 文件时，工具会提取其中 嵌入的 ICC 配置文件 并加入池中。它只读取文件的元数据，从不读取像素。对于 HEIC 和 AVIF，工具会遍历文件的 box 结构，因此在任何浏览器中都可使用，包括无法显示这些格式的浏览器。JPEG XL 文件同样会被拒绝：其配置文件压缩在码流内部，而 profiletool 目前尚不能解压。与 HEIC 共用容器格式的视频和相机 RAW 文件（MP4、QuickTime、Canon CR3）不会被视为图像。OpenEXR 或 Radiance HDR（.hdr）文件会被拒绝并给出原因：这两种格式都没有存放 ICC 配置文件的位置。OpenEXR 通过色度坐标描述颜色，Radiance HDR 则通过可选的 PRIMARIES 标头行描述。如需 查看 图像，请使用 HDR 标签页。＋ 从 .cube 新建 按钮可从 .cube LUT 构建 DeviceLink。结果会加入池中并在 配置文件 标签页中打开；在您点击 保存 ICC 配置文件 之前不会下载任何内容。

只有当文件前 36 个字节中包含 acsp 签名，且能通过 IccProfLib 的 ValidateIccProfile 解析时，该配置文件才会被接受。未通过的文件会列在拒绝摘要中并注明具体原因；其字节数据不会保留。

配置文件窗格

已加载的配置文件按 配置文件类别（输入、显示、输出、DeviceLink、ColorSpace、抽象、命名颜色……）分组到可折叠的分区中。ICC.1 第 8.7.1 条定义的 HDR ColorSpace 配置文件 则单独列在顶部的分区中（它们属于 ColorSpace 类配置文件，因此从 ColorSpace 分区中单独提出），并按传递函数分为 线性传递函数 和 非线性传递函数（PQ、HLG） 两组，每行以徽标标示其传递函数。这一划分在 HDR 标签页 中很重要：只有线性传递函数的配置文件才能指定给 OpenEXR 或 Radiance HDR 图像。每行显示文件名，以及类别、色彩空间、版本和大小的徽标；只能部分解析的配置文件会被标记。使用 A–Z 按钮循环切换排序方式（加载顺序 → 升序 → 降序），点击行上的 × 将其移除，拖动窗格右边缘的手柄调整宽度——也可以将窗格完全收起。

单击选中一行；按住 Ctrl/Cmd 单击可切换选中状态，按住 Shift 单击可选择一个范围。将行从池中拖到某个标签页上，即可在该标签页中使用它们。

池仅在当前会话中有效。 不会上传任何内容，也不会持久保存任何内容——您的文件系统才是永久存储。重新加载页面会清空池。

标签页功能

比较叠加显示 两个或更多 配置文件的色域。

“光谱”和“HDR”标签页直接接收图像文件，而不是池中的配置文件。其他每个标签页各自保留一组配置文件，以可移除的标签片显示在标签栏下方，并在标签页上以计数徽标显示数量。加载的第一个配置文件会自动在 配置文件 标签页中打开；此后，请从池中拖到您需要的标签页上。直接将文件拖放到某个标签页上，可一步完成加载到池中 并 放置到该标签页上。

2. 设置面板

点击屏幕右边缘的 ⚙ 按钮（在移动设备上为右上角的齿轮图标）即可打开设置。面板会滑出覆盖在内容上方，而不会改变内容的尺寸。

⚙ 下方还有两个按钮：

  • ? 在 应用内 打开本指南，以窗格形式从窗口侧面滑入。其标题栏中有搜索框——输入文字即可高亮匹配项，然后用 Enter / Shift+Enter（或 ˄ ˅ 按钮）逐个跳转；Escape 清除搜索，再按一次 Escape 关闭窗格。
  • ✉ 在新的浏览器标签页中打开 colourbill.com 上的联系表单。

面板分为两组：显示 和 环境。拖动面板左边缘可调整其宽度（220–560 px）；宽度会被记住。

背景

在 浅色、深色 和 系统（跟随操作系统偏好）主题之间切换。所选设置会跨会话保留。在 系统 模式下，应用会监听 prefers-color-scheme，并在操作系统主题变化时自动切换；明确选择“浅色”或“深色”则会取消该监听。

数字格式

选择数值在各配置文件视图中的显示方式——十六进制 或 十进制。

语言

覆盖界面语言。系统默认 (…) 会检测浏览器的区域设置并使用最接近的受支持语言，括号中显示该语言的本地名称，以便您看出选中的是哪一种。翻译范围涵盖应用界面：配置文件窗格、标签页名称、链接、光谱和 HDR 工具、标签视图中的 HDR 增益曲线视图、设置面板（包括“环境”及其中的原因说明），以及本指南的界面部分。部分文字不会翻译：

  • 由 IccProfLib 生成的文字——标签描述、验证消息、标头字段名——来自 C++ 库，保持英文。
  • 浏览器标志的名称保持英文，以便与浏览器自身的标志页面一致。
  • “环境”面板中的 显示事件 日志保持英文，以便原样粘贴到错误报告中。
  • 本指南遵循同一设置，但其中的 HDR 章节除外：在 HDR 支持处于测试阶段、文字仍在修改期间，这些章节保持英文。自上次翻译更新以来英文原文有修订的章节也会以英文显示并附有说明，直到译文跟上为止。

支持的语言：English、Français、Deutsch、Italiano、Español、Português (PT)、Português (BR)、Svenska、中文（简体）、中文（繁體）、日本語、한국어。chardata 的设置面板提供相同的语言集，因此在一个应用中切换语言后，在另一个应用中也能获得一致的阅读体验。

环境

显示 当前 浏览器、平台和显示器的能力，以便在某种格式或 HDR 功能不可用时，您能看出原因。从上到下依次为：

  • 摘要 — 浏览器和操作系统，以及显示器是否报告支持 HDR。
  • 浏览器标志（Chrome、Edge、Opera、Brave）— Experimental Web Platform features 是否已开启。该标志会启用 HDR 画布，并允许页面读取显示器的 HDR 余量。

    • - 当已知该标志处于关闭状态时，此框会高亮显示。如果此浏览器没有可用的 WebGPU，它会被标为 必需，因为此时 HDR 画布是渲染 HDR 的唯一途径；否则标为 可选。 - 检查配置文件从不需要它。 - 网页无法打开或更改浏览器标志。请点击 复制，将地址粘贴到地址栏，把该标志设为 Enabled，然后重新启动浏览器。

  • 显示器信息 — HDR 显示器、广色域（sRGB、Display P3 或 Rec. 2020）、像素比，以及当前使用的 HDR 画布路径（float16-canvas、webgpu 或无）。当您把窗口拖到这些属性不同的屏幕上时，它们会自动刷新。切换发生在窗口的大部分移到新屏幕上时。
  • 识别显示器（Chromium 系浏览器）— 请求权限以查看窗口位于哪台显示器上。获得许可后，即使在外观相同的显示器之间移动，面板也会刷新，并显示 当前显示器 的名称；在浏览器提供该信息时（开启上述标志的 Chrome）还会显示 HDR 余量，例如 1.35 档（≈ SDR 白的 2.55 倍）。如果您拒绝了该权限，请在网站设置中更改。
    • - 余量是 SDR 白之上的空间，因此在笔记本电脑内置的 HDR 面板上，调高亮度时余量会减小（SDR 白变亮，而面板峰值不变），调低亮度时余量会增大。观看 HDR 内容时，请调低亮度。 - 在 Windows 上，亮度改变后需等待几秒钟，待显示驱动报告后才会得到新值。当窗口移到另一块屏幕，或 Chrome 重新成为活动应用时，也会刷新。
  • 显示事件 — 可折叠的日志，记录最近 20 次刷新及其触发原因。报告显示问题时很有用。
  • 格式表 — 每种格式一行（ICC 配置文件、TIFF、PNG、JPEG、OpenEXR、Radiance HDR、AVIF、HEIC/HEIF、JPEG XL），回答三个问题：
    • - 检查：能否读取嵌入的配置文件？ - 显示：能否显示像素？ - HDR：能否渲染高于白色的亮度？

将鼠标悬停在某行上可查看 ✕ 的原因；无法显示的格式及其原因会列在表格下方。圆点标记的是由 profiletool 自行解码的格式，它们在所有浏览器中表现一致。除 JPEG XL（其配置文件压缩在码流内部）外，所有格式的 检查 一栏均为 ✓。

3. 配置文件视图

将配置文件从池中拖到 配置文件 标签页上即可检查它。该标签页会显示一个栏，其中包含文件名和 保存 ICC 配置文件 按钮（编辑后还会出现 ● 已修改 — 尚未保存 标记），下方是查看器：标题栏（文件名 · 字节大小 · IccProfLib 版本 · 有效性徽标）以及它自己的标签栏。

徽标汇总了 验证 报告：没有检查失败或警告时显示绿色 通过，至少一项检查给出警告时显示琥珀色 警告，任一检查失败时显示红色 失败。

部分解析的配置文件：如果配置文件损坏到验证器只能读取其结构，会出现警告横幅，且只有 标头 和 标签 标签页可用——验证、分析、XML 和 JSON 标签页会被隐藏，因为不得应用该配置文件。

3.1 标头

一个两列表格，列出 ICC 配置文件 128 字节二进制标头中的每个字段。数值通过 IccProfLib 的 CIccInfo 解码为易读的文字（展开签名、格式化日期、转换定点数值）。配置文件 ID（标头中的 MD5 哈希值）显示在顶部的高亮条中。

3.2 标签

一个六列网格，列出配置文件标签目录中的每个标签：

列含义

标签按偏移排序。填充 列按颜色区分——Pad < 0（标签重叠，不合规）显示为红色；Pad > 3（填充超出规范）显示为琥珀色。

点击任一行 即可就地展开（手风琴式——一次只展开一个标签）。展开的详情最后总是完整的类型专属描述——相当于运行 IccProfLib 的 CIccTag::Describe(verbosity = 100)。对于含有大型 CLUT 或曲线的标签（例如 A2B0、B2A0），描述中会包含每个网格单元或曲线点。

转换求值器

对于 LUT 转换（A2B / B2A / 预览标签），求值 分区直接使用 IccProfLib（不借助外部色彩引擎），将该标签的转换应用于您提供的单个颜色。方向由标签决定（A2B 为设备 → PCS；B2A 为 PCS → 设备），渲染意图也由标签隐含（…0 感知，…1 相对比色，…2 饱和度）。

  • 输入可以是 浮点值（设备通道值，或以可读的 Lab/XYZ 单位表示的 PCS 值）；当标签含有 CLUT 时，也可以按 网格点 索引（网格上的节点位置）输入。
  • 输出 同时 以内部归一化的 0–1 编码和可读单位（PCS 结果为 Lab/XYZ）显示。

色域标签（gamt）没有求值器——它是单通道的色域内 / 色域外映射，而不是可逆的转换；取而代之显示其色域图像。

HDR gain curves (HAGC)

This section is in English only. It describes HDR support, a beta feature that follows a draft ICC amendment and is still changing. It will be translated once the feature and its text are stable.

A headroomAdaptiveGainCurveTag says how an HDR ColorSpace Profile's image should be tone-mapped for displays with different amounts of headroom. Expanding the tag shows two views:

  • Gain curve plots the control points exactly as stored in the file, one line per alternate image. It is absent when the tag stores no alternate images. The x axis is the curve input: linear light, with 1.0 at the tag's HDR reference white. The y axis is the gain in stops, which is negative for an alternate that tones down.
  • Gain at a display headroom shows the curve as a colour-managed transform applies it, computed by IccProfLib's own evaluator. Drag Display headroom from 0 to 6 stops; it starts at the tag's baseline, and Baseline returns there. Two plots follow the slider:

    • - Gain applied at this headroom: the blended curve, drawn against every curve in the tag; - Grey tone curve at this headroom: what a grey input becomes, drawn against no change and the display peak.

Three more views make the adaptation visible: - Preview through the colour engine runs one test strip through IccProfLib's HDR transform twice: a grey ramp, then pure R, G, B, Y, C and M bands, all rising left to right in the profile's own signal (PQ, HLG, or Linear on a log scale). The top strip is as authored, at the baseline headroom where the tag applies no gain. The bottom strip is tone-mapped for the slider's headroom. Both are capped at that headroom's peak, the way a display with that much headroom would show them. Where the top strip clips to flat, the gain curve rolls the highlights off. Ticks mark where the ramp reaches reference white and the display peak. The strips use the same HDR output as the HDR tab: on an HDR display, values above SDR white look brighter than it. - Gain across every headroom is a heatmap of the gain on a grey input. The horizontal axis is input brightness, in stops relative to HDR reference white; the vertical axis is display headroom from 0 to 6 stops. Blue compresses, red expands, white leaves the input unchanged. Dotted lines mark the curves stored in the tag, the solid line the baseline, the amber line the slider, and the dashed diagonal where the input reaches the display peak. Click the heatmap to move the slider to that headroom. - Grey tone curves by headroom overlays the tone curve at each headroom the tag stores, shaded from blue (low) to red (high), with the slider's curve in amber. Both axes are in stops, so the diagonal means no change.

A note appears when slopes or whole curves are derived rather than stored. Another appears when the headroom is outside the tag's range, in which case the nearest curve is used unchanged.

Two cases have no curves to draw, and the view still explains them: - Tone mapping on, no alternate images. The tag asks for no tone mapping, only a clamp to what the display can show. The gain is zero at every headroom, and the preview strip shows the clamp. - Tone mapping off (the tag's Headroom Adaptive Tone Map flag is clear), or a tag IccProfLib cannot apply. The view says why IccProfLib declines, and a colour engine falls back to the next tone-mapping method (clause 8.7.1.3).

3.3 验证

针对已加载的配置文件运行 ICC 配置文件评估工作组（Profile Assessment Working Group）检查清单，并以报告形式显示。这些检查来自 iccDEV 的 iccPawgReport 工具，它被编译为单独的 WebAssembly 模块，仅在您首次打开此标签页时才会获取。（标题栏中的有效性徽标也由同一报告驱动；通过 URL 启动时，可用 VAL 或旧代码 PAWG 打开此标签页。）

每项检查归入 安全性、符合性 或 质量 之一，并给出一个判定结果。含有 HDR 内容的配置文件还有第四组 HDR。其中第一项检查报告该配置文件是否为符合规范的 ICC.1 HDR ColorSpace 配置文件（第 8.7.1 条），其余各项检查该条所依赖的 HDR 元数据：

判定含义
通过（PASS）检查成功
警告（WARN）不致命但值得复查的问题
失败（FAIL）配置文件不满足该检查
缺口（GAP）该检查无法完整评估（例如尚未实现）
不适用（N/A）该检查不适用于此配置文件
未运行（NOT RUN）该检查被跳过

顶部的汇总行以彩色标记统计每种判定的数量。点击标记即可筛选 下方的报告——蓝色光晕标示当前显示的类别，数量为零的标记处于非活动状态。例如，关闭 PASS 和 N/A，即可只关注警告和失败项。

3.4 分析

根据配置文件的色彩转换得出的整体质量分析——由专用的 WebAssembly 模块（iccDEV 可视化引擎）计算，该模块仅在您首次打开此标签页时获取，结果以应用自身的风格绘制。

每项分析都是一个可折叠的分区，且 所有分区初始均为折叠状态。这是有意为之：每个分区都要对配置文件完整执行一遍转换计算，因此由您明确选择打开哪一个，而不是在切换标签页时同时启动六项分析。结果会被缓存，因此重新打开分区是即时的。不适用于已加载配置文件的分区会改为显示简短的 不适用 说明（例如，矩阵 / TRC 显示器配置文件没有可供分析的设备↔PCS CLUT）。

特性文件统计

针对 一个 选定渲染意图的整体配置文件指标，由两个列表框和一个复选框控制：

  • 渲染意图 — 感知 / 相对比色 / 饱和度 / 绝对比色。
  • 往返类型 — 要报告的精度指标（见下文）。
  • 使用 MPE（颜色）标签 — 关闭 = 比色查找表；开启 = 多处理元素 / 颜色标签。它对色域内概览不起作用，在该模式下被禁用。

表格显示 色域体积（单位为 ΔE*ab³，即设备 → PCS 的 A2B 转换所包围的体积，通过将边界体素化并统计被包围的单元计算），以及所选往返的 最小值 / 平均值 / 标准差 / P90 / 最大值 ΔE*ab。下方是 ΔE 分布直方图——相对频率柱状图加累积频率曲线——以及误差最大处的 L, a, b；对于 PRMG，还会显示该配置文件是否隐含感知参考媒介色域。

四种往返类型：

  • 色域内概览 (RT0) — 将设备值网格转到 PCS、转回设备，再转到 PCS；在两次 PCS 结果之间测量 ΔE*ab。这是快速的色域内稳定性检查。
  • 反演 + 色域 (RT1) — 每个设备颜色的 PCS 值，与其经过一次 Lab → 设备 → Lab 往返后的 PCS 值之间的 ΔE*ab。它同时反映反演精度 和 色域映射。
  • 可重现性 (RT2) — 第一次与第二次往返之间的 ΔE*ab：反映重复往返的稳定程度，与第一次往返的色域裁剪无关。
  • PRMG 互操作性 — 对感知参考媒介色域内的 PCS 颜色做一次往返；ΔE 分布反映跨配置文件的互操作性。

直方图下方的 按明度的往返 ΔE 回答了汇总数字无法回答的问题：反演在色调范围的 哪个位置 出现困难，问题又 深入色域多远。

它对 32 个明度级别进行采样。在每个级别上，先在 色域边界上 取 64 个点，然后将它们分别向中性轴收缩到其彩度的 80 %、50 % 和 20 % 再各取一遍——共 8,192 个点，每个点单独绘制，各级别之间以虚线分隔。

请逐段阅读。在一段之内，点从左侧的色域表面排列到右侧的中性点，因此误差应在这一段内 逐渐下降：靠近边界的颜色最难反演，靠近中性的颜色最容易。如果某一段的误差一直到中性都居高不下，说明该配置文件在这一明度上有问题。最高的尖峰标示的是色域边界本身反演效果最差的明度级别。

每个种子点按构造都位于色域内，因此您看到的是真实的 B2A/A2B 不一致，而不是颜色因无法达到而被裁剪。请注意，此图有其 自己的 采样方式——有意偏重色域边界——因此其平均值和最大值会高于上表，且不可与上表直接比较。它跟随渲染意图，但不跟随往返类型。

缺少某项指标所需设备↔PCS 转换的配置文件会显示 不适用 说明；设备色彩空间太大而无法采样时，会报告为已跳过，而不是报错。

极值比色

配置文件再现范围的两端——印刷操作员通常最先查看的数字。

  • 白点 — 零着色剂 的颜色，即裸露承印物的颜色。
  • 黑点 — 将 PCS 黑（L*=0，a*=b*=0）送入所选的 B2A 表，得到配置文件为黑色 选择 的墨量，再将该墨量经 A2B1 读回而求得。
  • 两者都以 相对 和 绝对 比色显示。绝对比色显示承印物本身的颜色（偏蓝的白纸读数约为 L* 95、b* −4）；相对比色则将其重新参照到理想白。如果两列完全相同，这是正常的——只是媒体白恰好与光源一致。没有媒体白点标签的配置文件只显示相对值。
  • 黑点处的墨量 和 TAC — 该黑色下每个通道的墨量及其总和：总面积覆盖率，即墨量限制值。

由于每个 B2A 表都为黑色选择自己的墨量，黑点在不同意图之间确实不同——因此提供了渲染意图选择器。

其下方是 实地与最大彩度：对每个油墨角点（C、M、Y、R、G、B 和 K），给出它在色相 / 彩度 / 明度上的落点，以及从裸露承印物到该点的途中找到的彩度最高的点。这些行通过 A2B1 测量，因此 不随意图选择器变化。在表现良好的配置文件上，这两行一致。当最大彩度在实地 之前 就已达到时，该行会被标记：超过该点后，增加的墨量不再提高彩度，只会使颜色变暗。

仅适用于输出（打印机）配置文件 — 该分析假定零着色剂即裸露承印物。按色相的表格还要求 CMYK 或 CMY 设备色彩空间：n 色（nCLR）配置文件的通道可按任意顺序命名，因此无法确定哪个通道是“青”，表格会如实报告这一点，而不是猜测。

中性轴墨量

沿中性轴（a*=b*=0）从白（L*=100）扫描到黑（L*=0），通过配置文件的 B2A（PCS → 设备）表，绘制配置文件沿途施加的每种设备着色剂的量——即经典的 GCR / 中性灰构成曲线。每个设备通道一条曲线，按着色剂区分颜色。

在分色曲线之上还绘制了另一条曲线：

  • L* 输出（色调） — 色调响应：中性轴经过配置文件往返后实际落在的明度。从其形状可读出两点。低于对角线的下凹意味着灰色比要求的更暗。更有用的是，曲线 在配置文件可达到的最暗明度处变平——这个平台 就是 媒体黑点，它应与上文的极值比色分区一致。

仅适用于输出（打印机）配置文件；其他类别的配置文件会显示说明。

暗调中的用墨

在一个恒定且刻意选取的较暗明度上，沿 a*b* 平面上的四条直线路径——0°、45°、90° 和 135°——送入所选的 B2A 表，并为每条路径绘制得到的分色结果。

由于路径上的每个样本都具有相同的 L*，某种着色剂出现的任何突变或反转都仅源于色相和彩度的处理。这是暗调色域映射瑕疵的特征，在印刷中会表现为暗部的条纹或突然的颜色偏移。路径从色域外很远处出发，穿过色域，再从另一侧穿出，因此您还能看到配置文件从哪里开始截断。

明度平面自动选取：位于配置文件蓝色角点与 C、M、Y、R、G 中最暗者之间的中点。对于感知和饱和度表，明度会先从媒体黑点拉伸到 PCS 黑——这些表期望黑色位于该处——该分区会同时报告补偿后的平面和原始平面。

仅适用于输出（打印机）配置文件，且与上文按色相的表格有相同的 CMYK/CMY 限制（平面由油墨角点推导）。

经中性轴的原色墨路

三条路径——青→红、品红→绿、黄→蓝——每条从一个原色角点出发，在两个端点的中点明度处 经过中性轴，到达相对的角点，送入所选的 B2A 表并以分色形式绘制。

这是“暗调中的用墨”在色域内的对应分析。在那里，路径有意延伸到色域外以暴露色域映射瑕疵；而在这里，每个样本按构造都位于色域内——两个端点都是配置文件自身的原色，转折点位于中性轴上。因此，着色剂沿这些路径出现的台阶、拐折或反转不能归咎于色域裁剪：它是 CLUT 平滑性缺陷。中性转折点位于每幅图的中点，在那里您应看到平衡的中性灰构成。

对于感知和饱和度表，明度会针对该意图进行黑场补偿，与“暗调中的用墨”完全相同。

仅适用于输出（打印机）配置文件，且有相同的 CMYK/CMY 限制（角点与按色相的表格来源相同）。

墨量统计

配置文件施加的每种着色剂的量，以平均覆盖率和 占总量的比例 表示——即分色的耗墨特征。

表格沿中性轴对每种着色剂求和，并报告其平均覆盖率及其在全部用墨中所占的百分比。占比一栏最具诊断价值：它是配置文件中性灰构成的指纹（偏重青色的灰平衡与偏重黑色的灰平衡读数不同），且与采样数量无关。

第二个表格——所有色域边界上及色域内颜色 的用墨——标为 待定：它需要尚未构建的色域边界构造。

仅适用于输出（打印机）配置文件。

CLUT 图像

设备↔PCS 转换的颜色查找表，平铺成一幅图像，并可选择要查看哪个渲染意图表（A2B0–A2B3、B2A0–B2A3 以及预览表）。可用于一眼发现表中的结构性损坏。使用画布上的控件进行缩放、平移和复位。

选择 B2A（PCS → 设备）表 时，网格下方会出现 每种着色剂的灰度墨量覆盖图像——即各油墨的分色图，越暗表示该油墨越多。由于该分区打开时显示的是 A2B 表（其输出为 L*a*b*，而非墨量），分区顶部会有提示引导您查看这些图像。对于 n 色（nCLR）输出——5、6 或 7 色——由于没有简单的彩色预览，主图像会 通过配置文件的正向 A2B 进行色彩管理，从而仍以真实颜色呈现，而不是单通道灰度。

色域图像

色域标签的色域内 / 色域外映射：PCS 颜色可再现处显示为中性，超出设备色域处显示为红色。仅当配置文件含有 gamt 标签时才会出现。

4. 链接标签页

profiletool 将每个已加载的配置文件保存在左侧的 配置文件池 中。顶部有五个标签页——配置文件（即上文所述的单配置文件查看器）、比较、链接、光谱 和 HDR。链接 标签页用于将配置文件串联起来并加以使用：构建 DeviceLink、通过链条 转换图像 或 转换色彩数据集。

4.1 构建链条

将一个或多个配置文件从池中拖入“链接”卡片，即可按顺序将它们加入链条。链条是一个 纵向堆叠：源在顶部，目标在底部。每个配置文件贡献 一个转换，工具会显示进入和离开该转换的色彩空间（例如 RGB → Lab），并在各阶段之间的连线上标注 连接空间。引擎会实时验证整个链条，并报告端到端的流向（例如 链条：RGB → CMYK），或逐阶段说明在何处无法衔接。

  • 重新排序：拖动阶段的抓手（⠿）或使用 ▲ / ▼ 按钮；点击 × 移除阶段。
  • 翻转方向 — 首个转换的 ⇅ 按钮会反转链条方向，并依次影响后续各阶段。
  • 渲染意图 — 可通过 渲染意图（全部） 为整个链条选择一种，也可用各阶段自己的列表框单独覆盖。将鼠标悬停在任一控件上可查看所选意图的说明。除四种基本意图外，含有所需表格的配置文件还提供 no D2Bx/B2Dx 和 + BPC（黑场补偿）变体。
链中包含 HDR ColorSpace 配置文件。 ICC.1 HDR ColorSpace 配置文件没有 TRC 标签——第 8.7 条没有为 ColorSpace 配置文件定义 TRC 标签——因此经过它的转换使用其 AToB0Tag。该表即第 8.7.1.5 条为不具备 HDR 处理能力的软件所要求的 HDR→SDR 渲染。当链条中包含 HDR ColorSpace 配置文件时，卡片会对此加以说明：您生成的 DeviceLink、图像或数据反映的是这一 SDR 回退，而不是配置文件的 HDR 行为。

4.2 生成 DeviceLink

将整个链条烘焙为单个 DeviceLink 配置文件（iccDEV iccApplyToLink 的浏览器内移植）。为其命名并点击 生成 DeviceLink；结果会像其他配置文件一样进入池和“链接”累积区，可在配置文件标签页中检查，或在另一个链条中复用。

4.3 转换图像

将一幅栅格图像（TIFF、PNG 或 JPEG）拖入图像槽，点击 转换图像 即可让它通过链条（iccApplyProfiles 的浏览器内移植）。图像会先经过仅读取标头的探测验证——其色彩空间必须与链条的输入匹配。结果会 下载；图像从不存入池中。

加载有效图像后，会出现 图像输出选项 面板，其中的目标参数与 iccApplyProfiles 命令行工具一一对应：

  • 编码 — 与源相同、8 位、16 位或 浮点（32 位）。
  • 压缩 — 无、LZW 或 ZIP（Deflate）。
  • 平面格式 — 交错（chunky）或 分离 平面。
  • CMM 插值 — 四面体 或 线性。
  • 嵌入 ICC — 在输出中标记链条的最后一个（输出空间）配置文件。

默认设置下，RGB/灰度输出保存为 PNG；选择仅 TIFF 支持的选项（浮点、LZW/ZIP 或分离平面）会将容器切换为 TIFF。

嵌入的配置文件：如果拖入的图像带有自己嵌入的 ICC 配置文件，会出现横幅提示可将其 提取——一键即可将该配置文件加入池中，并放到链条开头（作为其源空间）。

4.4 转换数据

将色彩数据集（CGATS/IT8、CSV、CxF 或 JSON）拖入数据槽，点击 转换数据 即可让每个色块通过链条（相当于 iccApplyNamedCmm）。工具会读取数据集中包含的数据种类（设备 / Lab / XYZ / 光谱），并提供链条输入所需的那一种；光谱 输入会用 iccDEV 的标准计算器换算为色度值，所用的 观察者 和 光源 由您选择。可以过滤重复的色块（取中位数或平均值）。结果会在表格中打开，您可以将其 保存 为 CSV。

4.5 观察者变换

“链接”标签页包含 两张 生成器卡片。在“链接流水线”上方，观察者变换 卡片可由一个 V5 RGB 显示器配置文件加一个 V5 观察者（PCC）配置文件，构建 v4.3 矩阵 / TRC 显示器配置文件。将两者都拖到卡片上——它们会按配置文件类别自动分配到 V5 RGB 显示器 和 V5 观察者 (PCC) 槽中——然后点击 创建 V4 显示器配置文件，为其命名，再点击 创建。结果会加入池和此标签页。两者都不是的配置文件会被忽略并给出警告。

4.6 比较与光谱标签页

比较 标签页叠加显示池中两个或更多配置文件的色域边界——一个 3D 外壳加一个 2D 明度切片——以便看出它们的差异。当配置文件是 HDR ColorSpace 配置文件时，显示 SDR 回退 说明会解释：每个色域都是由 AToB0Tag 的 SDR 渲染构建的，而不是由配置文件的 HDR 范围构建，因为后者无法在有界的 PCS 中绘制。光谱 标签页将一组单通道光谱图像（按通道顺序拖入）组装成一个多通道 TIFF（iccSpecSepToTiff）。

Radiance HDR. profiletool reads run-length-encoded and flat RGBE files in any orientation. The stored values are shown as they are: an EXPOSURE line is not undone. XYZE files are refused, and so is any image over 40 megapixels. So is a file whose pixel data is too small for its size: at most 64 pixels per byte, four times what run-length encoding reaches on a flat scanline. Old-style repeat markers could otherwise describe a 40-megapixel image in about 75 KB.

On the slider, 0% is the SDR rendering and 100% is no limit. Values in between cap brightness smoothly at that many stops above SDR white (0 to 6 stops), shown beside the slider.

Matching the display. The panel tracks the monitor the window is on: drag it to another screen and the facts and notes update.

It comes from the headroom the browser reports; see Environment, where Identify displays grants the permission (the button also appears here). An SDR display reads 1× — SDR display. When the browser does not report a peak, the panel says so rather than guessing.
  • When an OpenEXR or Radiance HDR image asks for more than the display shows, a note says so — for example asks for 4.93×, this display shows up to 2.23×. Values above the display's peak then clip to flat white, which is why the SDR and HDR ends can look alike even on an HDR monitor.
  • Fit to display sets the limit to the display's peak, so highlights roll off into it instead of clipping. On an SDR display that means the SDR rendering. On Windows the reported peak can lag behind brightness changes; the value is shown so you can judge.
  • An SDR white patch — plain white — sits against the image's right edge, for comparison by eye. Drag it anywhere over the viewer (or focus it and use the arrow keys; Shift for bigger steps), and double-click it to put it back beside the image. The SDR white patch button above the image turns it on and off. Its position and on/off state are remembered. On an HDR display with real HDR output, highlights look brighter than the patch; at the SDR end the brightest pixels sit just below it, because the SDR rendering eases highlights in under white. If highlights never look brighter, the output is being clamped.

Assigning an HDR profile. For TIFF, PNG, JPEG, OpenEXR and Radiance HDR, Assign profile chooses a profile to interpret the image's pixel values:

  • the image's embedded profile;
  • any HDR ColorSpace Profile in the pool (load one in the Profiles pane first);
  • None, to go back to what the file itself signals.

A TIFF starts with its embedded profile selected, since without one its values mean nothing.

With a profile assigned, profiletool decodes the image itself and runs it through IccProfLib's HDR colour-management path, as the ICC.1 HDR amendment (clause 8.7.1) describes. The profile's transfer function (PQ, HLG or Linear) converts the code values to light, its gain curve tone-maps them, and its cicpTag primaries set the colour. 1.0 lands on the profile's HDR reference white, which is shown at the display's SDR white.

  • Target headroom (0 to 6 stops) is the display the image is being prepared for. The profile's gain curve is evaluated there, the same curve Gain at a display headroom plots in the Tags tab. Fit to display sets it to this display's peak.
  • Tone mapping chooses the method: Auto (the clause 8.7.1.3 recommended ranking), Gain curve only, the profile's Baked SDR fallback (AToB0Tag), or Off, which behaves like a colour engine that predates the amendment. The baked fallback is only as good as the table the profile carries. A table baked from the gain curve (for example by iccDEV's iccHdrFallback) gives a proper SDR rendering. A placeholder table of identity curves passes the raw PQ or HLG signal values through, and the image looks flat and too bright.
  • The panel reports what the colour engine actually did: which path (HDR with the gain curve applied, HDR without a curve, or the baked table), the transfer, and the HDR reference white. A profile without a gain curve still takes the HDR path, but tone-maps nothing, so the Dynamic range limit is what keeps its highlights within the display.
  • Pooled HDR ColorSpace Profiles appear in two groups, Linear transfer and PQ / HLG transfer, matching the Profiles pane. OpenEXR and Radiance HDR store linear light, so for those images only the Linear transfer group is offered. A note under the list says so, and how many PQ/HLG profiles are hidden. Assigning needs a 3-channel RGB image.
  • A profile whose cicpTag declares ColourPrimaries 2 (Unspecified) is listed with the note Unspecified primaries: no HDR path in this build. Clause 8.7.1.1 takes such a profile's primaries from a cicpType chromaticity extension (clause 10.3) whose format is not yet available to profiletool, so no policy can give it an HDR rendering. Every policy renders it through its AToB0Tag instead — Auto and Gain curve fall back to the same SDR rendering as Baked SDR fallback and Off — and Colour engine path says Baked AToB0 — not the HDR path. That fallback is a temporary measure in IccProfLib while the ICC settles how such a profile should be handled.
  • Linear values (OpenEXR, Radiance HDR and floating-point TIFF only) says what a file value of 1.0 means. The two conventions disagree. These files usually put SDR white at 1.0, but an ICC Linear transfer reads 1.0 as 1 cd/m² (ICC.1 clause 8.7.1.2 a) and then divides by the HDR reference white, so an unscaled image comes out a few hundred times too dark.

    • - File 1.0 = HDR reference white (the default) multiplies the pixels by the profile's HDR reference white first, so file 1.0 lands on it. The Input scale fact shows the factor, for example ×300. - File 1.0 = 1 cd/m² passes the values unscaled, as the clause reads them. Use it for files whose values really are in cd/m².

The choice is remembered.

Why some images look dim: browsers ignore HDR that is signalled only by an embedded ICC profile. A PNG or JPEG whose HDR lives in an ICC.1 clause 8.7.1 HDR ColorSpace Profile therefore looks flat here. The panel says so when that applies. Its profile is still fully inspectable.
Refusals name the reason. For example, HEIC display needs Safari: Chrome and Firefox decode HEIC on no platform. The image's profile can still be opened in the Profile tab.

Gain curves. An HDR ColorSpace Profile's adaptive gain curve is not shown here but in Profile → Tags. See HDR gain curves (HAGC) under Tags.

5. 往返编辑

XML 和 JSON 标签页都能将配置文件写回 ICC 二进制格式。典型工作流程：

1. 加载 一个 ICC 配置文件。 2. 打开 XML 或 JSON 标签页。点击 转换为 XML / 转换为 JSON 填充编辑器。 3. 在页面内的编辑器中 编辑。工具栏旁会出现未保存指示。 4. 点击 转换为 ICC。封装层会构建新的配置文件，重新运行验证，并更新标头 / 标签 / 验证标签页。 5. 配置文件标签页栏中的文件名旁会出现 ● 已修改 — 尚未保存 标记。 6. 点击 保存 ICC 配置文件。编辑后的字节会以 -edited.icc 的形式下载。

两个编辑器相互独立——先编辑 XML 再编辑 JSON 不会混合两条路径。保存的是最近一次生成的 ICC 字节。

注意：转换的保真度取决于 IccLibXML / JSON 封装层对各标签类型的支持程度。如果某种标签类型无法表示，往返过程会丢失细节；转换回来后，请查看验证标签页，确认一切仍能正常解析。

标签视图会高亮显示字节与原始加载时不同的标签，便于看出您的编辑改动了什么。

6. 从 chardata 启动

在 chardata 中加载 ICC 配置文件后，点击 显示文件 打开页面内查看器，然后点击 打开编辑器。此时会打开一个新标签页，URL 中带有 ?source=chardata。

交接完全在浏览器内完成：

1. profiletool 打开后检测到 ?source=chardata，并通过 postMessage 向 window.opener 发送 {type:'profiletool:ready'}。 2. chardata 回复 {type:'profiletool:load', filename, bytes}。 3. profiletool 接收字节数据（先根据允许列表验证发送方来源，并检查大小不超过 256 MB 上限），运行验证，然后显示配置文件。

无需上传，也没有服务器往返。数据流是单向的——在此所做的编辑需点击 保存 ICC 配置文件 保存，不会传回 chardata。

7. 通过 URL 启动

您可以通过一个链接打开工具，在链接中指定要加载的配置文件以及要打开的标签页，方法是使用 URL 片段（# 之后的部分）：

https://chardata.colourbill.com/profiletool#url=<profile-url>&tab=<tab>

两个参数都是可选的：

  • url= — 获取配置文件的网址。字节数据在您的浏览器中下载，然后经过与本地文件完全相同的处理路径：acsp 标头检查、完整的 ValidateIccProfile、256 MB 大小上限，以及针对无法解析的配置文件的尽力回退。不会上传任何内容——获取的字节只供验证器使用，从不重新发送。
  • tab= — 配置文件加载后要打开的视图。

完整示例：

https://chardata.colourbill.com/profiletool#url=https://example.org/profiles/sRGB.icc&tab=VAL
为什么用片段而不用查询字符串？ # 之后的部分从不会发送到 Web 服务器，因此您所检查的配置文件的地址只保留在您自己的计算机上。
